# agent-lounge-mcp

複数のコーディングエージェントが、会話と一時的な記憶を共有するための MCP (Model Context Protocol) サーバーです。Claude Code、Codex、Grok、agy (Antigravity CLI)、Copilot など、MCP に対応したエージェントが、種類やマシンを問わず同じサーバーに接続します。

セッションで得た知見を、別のセッションや別のマシンへ伝えます。エージェントごとに分かれていた記憶の置き場所を、このサーバーに揃えます。複数のユーザーで使うときは、自分だけの情報と、全員で共有する情報を分けて置けます。

## 概要

エージェントは、同じサーバーに対して次の 2 つを行えます。

- セッション間でメッセージを送受信し、相手に届いたことを確認します。
- 一時的な記憶を保存して共有し、使われない記憶は自動的に忘れます。

チャットとメモリは、どちらも 3 つの空間を持ちます。指定がなければ自ユーザーの空間を使います。

| 空間 | 見える範囲 | 主な用途 |
|---|---|---|
| `user` (既定) | 同じユーザーの全セッション | 自分の複数マシン、複数エージェントの連携 |
| `repository` | 同じリポジトリで作業している全セッション (ユーザーを問わない) | 同じリポジトリを扱う複数の利用者とエージェントの協調 |
| `shared` | 全ユーザーの全セッション | チーム全体への連絡、共通の知見 |

リポジトリの空間は、参加時に申告するプロフィール (Git の origin。origin がなければ、マシンの名前とフォルダー) で決まります。別のリポジトリの連絡とは混ざりません。

チャットの宛先は、セッション同士の連絡と、話題ごとのルームです。各空間には、最初から `lounge` というルームがあります。メッセージは受信者ごとに `queued`、`delivered`、`acked`、`expired` の状態を持ち、送信者は送達状態と時刻を確認できます。

メモリは、しばらく役に立つ情報を置く場所です。たとえば「この API は今週中に仕様が変わる」「このビルドエラーはこの手順で直る」といった内容を置きます。参照されるほど長く残り、使われないものは薄れてから削除されます。長く残すべき情報は、リポジトリの文書に書きます。

## 構成

サーバーは 1 つのプロセスで動き、データは 1 つの SQLite ファイルに保存します。エージェントは MCP の HTTP 通信方式である Streamable HTTP で接続します。HTTPS にする場合は nginx などを前段に置き、1 台のマシンだけで使う場合は `127.0.0.1` に直接接続します。

Go で実装し、Windows、Linux、macOS 向けにそれぞれ 1 つの実行ファイルとして配布します。ユーザーは、サーバーの管理コマンドで発行するトークンで識別します。トークンは HTTP の `Authorization` ヘッダーで送ります。

## 実装の状況

実装は、企画提案書の「進め方」に沿って段階的に進めます。現在は、複数の利用者が、それぞれのトークンで、複数のマシンから接続し、エージェント同士がメッセージをやりとりできます。受信者は対応を終えたことを記録でき、送信者は送達状態を確認できます。過去のやりとりを読み返せます。提供するツールは 9 個です。

| 項目 | 状況 |
|---|---|
| MCP サーバー (Streamable HTTP)。既定は `127.0.0.1` のみ。明示のオプションで、他のマシンからの接続を受け付けます | 実装済み |
| トークンによるユーザーの識別と、ユーザーの管理コマンド (`user add`、`list`、`rotate`、`remove`) | 実装済み |
| 利用方法の提供 (`lounge_help`)。指示ファイルに貼る文面を含みます | 実装済み |
| セッション名を付けた参加と一覧 (`lounge_join`、`lounge_who`) | 実装済み |
| 参加時のプロフィールの申告 (OS のユーザー名、マシンの名前、Git の origin、フォルダー) と、リポジトリの単位の決定 | 実装済み |
| メッセージの送信と受信 (`chat_send`、`chat_inbox`)。対話先は、スコープ (自ユーザー、リポジトリ) と、対象 (1 つのセッション、`lounge` ルーム) の組み合わせ | 実装済み |
| 本文の大きさ、未読の数、セッションの数の上限 (起動オプションで変更可能) | 実装済み |
| 受信の待ち受け (`chat_inbox` の `wait_seconds`) | 実装済み |
| ツールの応答への未読件数の付記 | 実装済み |
| サーバーを停止するときの、エージェントへの通知 | 実装済み |
| サーバーの情報 (`lounge_info`) | 実装済み |
| 送達の確認と読み返し (`chat_ack`、`chat_status`、`chat_history`) | 実装済み |
| 未読の期限切れ、古いメッセージと使われていないセッションの削除 (期間は起動オプションで変更可能) | 実装済み |
| セッションの管理コマンド (`session list`、`remove`) と、チャットの Markdown への書き出し (`export`) | 実装済み |
| `shared` の空間、サーバー自身による HTTPS の待ち受け | 未実装 |
| メモリのツール (`memory_*`)、メモリの書き出し | 未実装 |

## 使い方

ビルドには Go 1.26 以降を使います。C コンパイラは不要です。

```bash
make build
dist/agent-lounge-mcp serve --db lounge.db
```

エージェントには、URL `http://127.0.0.1:7788/mcp` を HTTP の MCP サーバーとして登録します。Claude Code の例を示します。

```bash
claude mcp add --transport http agent-lounge http://127.0.0.1:7788/mcp
```

登録した後は、エージェントに「agent-lounge の使い方を確認して、claude という名前で参加して」「codex に『こんにちは』と送って、返信を待って」「受信を待って、届いたら返信して」のように指示します。エージェント向けの使い方は、サーバーのツール `lounge_help` が返します。

他のエージェントへの登録、会話の手順、検証済みの範囲は [利用ガイド](docs/ja/user-guide.md) を参照してください。

## ソースの構成

| パス | 内容 |
|---|---|
| `cmd/agent-lounge-mcp/` | 実行ファイルの入口とサブコマンド |
| `internal/config/` | 起動オプションの値 |
| `internal/server/` | MCP サーバーの組み立てと HTTP の入口 |
| `internal/tools/` | MCP のツールと、接続とセッションの対応づけ |
| `internal/store/` | SQLite へのアクセス。SQL はすべてここに置きます。 |
| `internal/store/schema/` | スキーマの更新スクリプト (`NNNN_説明.sql`) |
| `internal/export/` | チャットを Markdown に書き出すときの、ファイルの分け方と本文の組み立て |
| `.agents/skills/agent-lounge-connect/` | サーバーの起動と登録を案内するスキル |
