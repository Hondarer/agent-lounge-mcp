## 2. プロフィールの正規化 (`internal/profile/`)

### 2.1. origin の相対パス

正規化済みの形 (`ホスト/パス`。方式もコロンもない値) は、最初の `/` の前の部分 (ホスト) が `.` を含むか、`localhost` であるときだけ受け付けます (大文字と小文字は区別しません)。それ以外は、ローカルの相対パスとして、origin がないもの (空) として扱い、エラーにしません。

| 入力 | 今 | 変更後 |
| --- | --- | --- |
| `github.com/owner/repo` | `github.com/owner/repo` | 同じ |
| `localhost/owner/repo` | `localhost/owner/repo` | 同じ |
| `foo/bar` | `foo/bar` | origin なし |
| `gitserver/team/repo` | `gitserver/team/repo` | origin なし |
| `foo` (区切りなし) | エラー (パスがない) | origin なし |
| `https://gitserver/team/repo`、`git@gitserver:team/repo` | `gitserver/team/repo` | 同じ (URL の形と `ユーザー@ホスト:パス` の形は変えません) |
| `user@host/path` (`@` があり、コロンがない) | `host/path` | 同じ (`@` がある値は、相対パスとして扱いません) |

### 2.2. WSL の共有の形のドライブのパス

`\\wsl.localhost\<ディストリビューション名>\mnt\<1 文字>\...` と `\\wsl$\<ディストリビューション名>\mnt\<1 文字>\...` (区切りが `/` の場合を含む) を、`<1 文字>:\...` (全体を小文字) にそろえます。`/mnt/<1 文字>/...` を `wsl_distro` とともに渡した場合と同じ値になります。

| 入力 | 今 | 変更後 |
| --- | --- | --- |
| `\\wsl.localhost\Ubuntu\mnt\c\Work\App` | `\\wsl.localhost\ubuntu\mnt\c\Work\App` | `c:\work\app` |
| `\\wsl$\Ubuntu\mnt\d` | `\\wsl.localhost\ubuntu\mnt\d` | `d:\` |
| `\\wsl.localhost\Ubuntu\mnt\data\x` (1 文字でない) | `\\wsl.localhost\ubuntu\mnt\data\x` | 同じ |
| `\\wsl.localhost\Ubuntu\home\..\mnt\c\x` | `\\wsl.localhost\ubuntu\mnt\c\x` | `c:\x` (`.` と `..` を解決した後で判定します) |

## 3. `chat_history` の存在しないルーム名 (`internal/tools/delivery.go`)

`room` が空でなく、`lounge` でもないとき、`chat_history` はエラーにします。エラーの文は、`chat_send` と同じ形です。

```text
no room named "<名前>": the only room is lounge
```

判定は、引数の検査 (`scope` の値、`room` と `with` の併用など) の後、データベースを読む前に行います。`room` に `lounge` を渡して、その空間のルームがまだ作られていない場合 (最初のメッセージの前) は、今と同じく、空の一覧を返します。

テスト: `internal/server/` の `chat_history` のテストに、存在しないルーム名のエラーと、`lounge` で空の一覧が返ることを加えます。

## 4. 無効になったトークンの待ち受け (BL-032 の 1 番)

### 4.1. 動作

待ち受け中の `chat_inbox` は、次の時点で、その要求のトークンがまだ有効かを確かめます。

- 待ち受けを始めてから 5[秒] ごと。
- 新着で起きたとき (メッセージを読む前)。

有効でない場合は、待ち受けをやめ、メッセージを渡さずに、次のエラーを返します。

```text
your token is no longer valid: it was replaced or its user was removed. Tell the user to update the token in this agent's MCP settings.
```

「有効」は、認証のときに使ったトークンのハッシュが、同じユーザーの行に今も記録されていることです (`user rotate` と `user remove` で、有効でなくなります)。トークンなしの要求 (ユーザー `local`) は、確かめません。

待ち受けない呼び出し (`wait_seconds` が 0、または未読がすでにある) は、今のままです (要求のたびの認証で足ります)。

### 4.2. 実装の形

- `internal/server/auth.go`: 認証したトークンのハッシュを、ユーザーとともに `tools.TokenInfo` に渡します。トークンそのものは、今と同じく渡しません。
- `internal/store/users.go`: ユーザーの ID とハッシュが今も一致するかを返す問い合わせを加えます。
- `internal/tools/chat.go` (待ち受けの繰り返し): 5[秒] の間隔の確認と、起きたときの確認を加えます。間隔は定数とし、テストで短くできるようにします。

### 4.3. テスト

- 待ち受け中に `RotateToken` を実行すると、間隔の後に、呼び出しが 4.1 のエラーで終わる。
- 待ち受け中にトークンを発行し直し、その後にメッセージを送ると、メッセージは渡されず、未読のまま残る。
- トークンが有効なままなら、今と同じく、新着で起きてメッセージを受け取る。
- ユーザー `local` の待ち受けは、確認を行わない。

## 5. セッションの存在の確認 (BL-033 の 4 番)

### 5.1. 動作

参加済みの接続のツールの呼び出しでは、ハンドラーの前に、最終利用時刻の更新を、セッションの ID、ユーザー、名前の一致を条件に行います。更新した行が 0 のときは、セッションが消えたものとして、今と同じ処理 (接続を参加していない状態に戻し、セッションが要るツールではエラーを返す) をします。`SessionExists` の問い合わせは、ツールの呼び出しでは使いません。

ハンドラーの後は、未読の数え上げだけを行います。

外から見える変化は、次の 1 点です。

- 最終利用時刻 (`lounge_who` の `last_seen` と、使われないセッションの削除の判断に使う値) が、失敗した呼び出し (引数の誤りなど) でも更新されます。今は、成功した呼び出しだけで更新されます。

サーバーが停止の処理に入った後の呼び出し (すべてエラー) では、今と同じく、更新しません。

### 5.2. 実装の形

- `internal/store/`: `Seen` を、存在の確認を兼ねた更新 (`Touch`。更新した行の有無を返す) と、未読の数え上げ (`Unread`) に分けます。`SessionExists` は、他に使う箇所がなければ削除します (テストでの利用は、置き換えます)。
- `internal/tools/tools.go` の `registerTool`: 上の順序に改めます。

### 5.3. テスト

- 既存のテスト (削除されたセッションの接続がエラーになる、参加の前から使えるツールは動く) が、そのまま成功する。
- 失敗した呼び出しでも、最終利用時刻が進む。
- `Touch` は、ID が同じでユーザーまたは名前が異なる行を更新しない。

## 6. 検証の基盤 (`scripts/interactive/`)

### 6.1. 許可の画面への応答 ((1))

- 定義 (`Definition`) に、`approvals` (画面の文字列と、応答のキーの組の一覧) を加えます。
- 指示への応答を待つ間 (`Agent.ask`)、画面に `approvals` の文字列が出たら、応答のキーを送り、回数を数えます。同じ画面に 2 回応答しないよう、応答の後は、その時点より後の出力だけを調べます。
- 応答した回数を、`Reply` に持たせ、各シナリオの結果に `approvals` として記録します。
- Copilot CLI の定義:
    - `approvals`: 「Do you want to run this command?」に Enter (「1. Yes」が選ばれた状態)。
    - 起動のオプションから `--allow-tool shell` を除きます。`--allow-tool agent-lounge` と `--allow-tool write` は残します (agent-lounge のツールとファイルの書き込みは、今と同じく、起動のオプションで許可します)。
- 他の 4 つの CLI には、`approvals` を定義しません (この環境の設定では、許可の画面が出ないため)。

### 6.2. 打ち直し ((2))

- 定義に、入力欄を消すキー (`clear_keys`) を加えます。5 つの CLI とも Ctrl+U です (WSL の側で確かめました。Windows の側は、6.8 の確認で確かめます)。
- `type_line` は、打ち直す前に、入力欄を消すキーを送ります。

### 6.3. 時間切れのときのプロセスの終了 ((4))

- 非対話の実行 (シナリオ 6 の `_one_shot`) を、`subprocess.run` から、プロセスのグループを分けた起動に改めます。時間切れのとき、プロセスのツリーを終了します (Windows は `taskkill /T /F /PID`、POSIX はプロセスのグループへの SIGKILL)。その後、出力の読み取りを待ちます。
- 登録と登録の解除の実行 (時間の上限 60[秒]) にも、同じ関数を使います。

### 6.4. 出力の検索 ((5))

- 端末 (`Terminal`) が、制御の列を除いた文字 (`screen.plain` の結果) を、届いた出力の分だけ足して持つ形にします。`wait_for` と `text` は、これを使い、呼び出しのたびに出力の全体を加工し直しません。
- 制御の列が、出力の区切りにまたがる場合も、全体を一度に加工した結果と同じになるようにします (自己試験で確かめます)。

### 6.5. 完了の判定 ((6))

- 定義に、作業中だけ画面に出る文字列 (`busy`) を加えます。

    | CLI | `busy` |
    | --- | --- |
    | Claude Code | `esc to interrupt` |
    | Codex | `esc to interrupt` |
    | Copilot CLI | `ctrl+c interrupt` |
    | Grok | `Ctrl+c:cancel` |
    | agy | `esc to cancel` |

- 応答の完了は、「完了の語が出た後、4[秒] 文字が出ず、かつ、今の画面に `busy` の文字列がない」こととします。`busy` がある間は、時間の上限まで待ち続けます。

### 6.6. 「ツールを呼ばない」指示の確認 ((8))

- シナリオ 4 と、シナリオ 5 の「どの指示ファイルを読むか」の質問で、質問の間に、その CLI の接続からのツールの呼び出しがあったかを、サーバーの接続の診断から調べ、結果に `tools_called_during_question` (呼ばれたツールの名前の一覧) として記録します。判定 (`passes_instructions`、`files_read`) は変えません。

### 6.7. 残ったプロセス ((11))

- コードは変えません。この案件の事前の確認の後に、基盤が起動した CLI のプロセスが残っていないことを確かめた結果を、確認の記録に書き、(11) を残課題から除きます。

### 6.8. 自己試験と実機での確認

- 自己試験 (`scripts/interactive/tests/`) に、次を加えます。CLI の代わりのプログラム (`fake_agent.py`) に、許可の画面、作業中の表示、Ctrl+U での入力欄の消去、子プロセスを残して止まる動作を加えます。
    - 許可の画面に応答し、回数が記録される。
    - 作業中の表示がある間は、完了としない。
    - 打ち直しの前に入力欄が消え、指示が重ならない。
    - 時間切れのとき、子プロセスも終了し、実行が戻る。
    - 出力を分けて届けても、検索の結果が全体を一度に加工した場合と同じになる。
- 実機での確認 ([Q-012](261120-small-fixes-discussion.md#q-012-基盤の直しの実機での確認)):
    - WSL と Windows の両方で、5 つの CLI のシナリオ 2 と 3 を 1 回ずつ、Copilot CLI のシナリオ 5 を 1 回 (5 回の実行) 実行します。
    - WSL は、このセッションが実行します。Windows は、Windows の側のセッション (`z8g4-base-polished-glade`) に委譲します。作業ブランチを GitHub に push し、Windows の側で取得して、サーバーをビルドし、自己試験とシナリオを実行して、結果のフォルダーの要約 (`verify.py summary`) を返してもらいます。
    - Windows の側で、`busy` の文字列、Ctrl+U、Copilot CLI の許可の画面が WSL の側と異なる場合は、定義を OS ごとの値にして直し、確かめ直します。
    - Codex の週の利用量の残りが 10% を切った場合は、Codex の実行をやめ、未検証として記録します (前の案件の利用者の指示を引き継ぎます)。

1. ブランチ `feature/small-fixes` を `main` から作り、作業前の記録の変更 (`docs/prompts/` の移動と新しい記録) を最初のコミットにします。

6. 承認を受けたら、追加の指示を待たずに、`main` にマージして push します ([Q-009](261120-small-fixes-discussion.md#q-009-作業ブランチと実装の担当) の補足: 「案件承認を以てマージ許可とします。」)。
