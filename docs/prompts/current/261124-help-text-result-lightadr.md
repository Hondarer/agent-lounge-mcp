## LADR-002 `lounge_help` の結果の形

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

Claude Code 2.1.331 は `lounge_help` の結果を `{}` として扱い、案内の本文を読めません (BL-049)。一方、Copilot CLI はテキストと構造化された結果の両方を受け取るため、構造化された結果に本文を入れると、一度に読める大きさを超えます (`../past/261119-connection-guidance-lightadr.md` の LADR-008)。

### 得られた事実

- Claude Code 2.1.331 は、構造化された結果があると、テキストの結果ではなく、それをモデルに渡します (`stream-json` の記録)。
- 出力スキーマを持たず、構造化された結果を返さない試作では、Claude Code がモデルに本文 (19,534 文字) を渡しました。
- go-sdk v1.8.0 の `mcp.AddTool` は、出力の型が `any` で値が `nil` のとき、出力スキーマも構造化された結果も作りません。

### 決定

`lounge_help` だけ、出力スキーマを持たず、テキストの結果だけを返します。参加の後は、今と同じく、最後の行に未読の件数の行を付けます。構造化された結果の `unread` はなくなります。他のツールの結果の形は変えません。

## LADR-003 確認の方法

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

`lounge_help` の結果の形の変更は、すべての CLI に渡る結果を変えるため、どの CLI で確かめるかを決める必要がありました。

### 得られた事実

- この WSL の環境で、Claude Code 2.1.331、Codex 0.171.0、Copilot CLI 1.0.114、Grok 1.0.92、agy 1.5.15 を使えます。

### 決定

5 つの CLI で、非対話の実行で `lounge_help` を呼ばせ、案内の本文を読めることを確かめます。CLI の利用の上限 (トークンの上限) に達して確かめられない CLI は、未検証とします。
