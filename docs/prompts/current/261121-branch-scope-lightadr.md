## LADR-001 案件の対象と進め方

決定者: Tetsuo Honda

## LADR-003 ブランチのスコープの形と範囲

決定者: Tetsuo Honda  
最終更新日: 2026-11-22

### 背景と課題

リポジトリよりも詳細な単位としてブランチを設ける形 (スコープの種類を足す、リポジトリの単位を分ける、プロフィールの項目にするだけ)、実現する利用場面、使える機能、他のブランチの内容の扱い、今の規則の当てはめを決める必要がありました。

### 得られた事実

- スコープは、種類ごとの規則 (識別子の決め方、範囲に入るセッション、ルームの置き場所) として 1 か所に定義されています (`internal/store/scope.go`。コミット `9b83815`)。
- チャットの送信とメモリの作成は、同じスコープの規則を使っています (`internal/store/chat.go` の `Send`、`internal/store/memory.go` の `CreateMemory`)。
- 今の仕様は、「セッションが使えるスコープは、自分が属する範囲だけ。他の識別子を指定する手段はない」としています (`docs/ja/reference.md` の「スコープと対象」)。
- `rooms`、`messages`、`memories` の `scope` には、値の制約 (CHECK) があります (`internal/store/schema/0002_repository.sql`、`0005_memory.sql`)。

### 決定

スコープの種類に `branch` を足します。範囲は、同じリポジトリの単位と同じブランチを申告しているセッションで、ユーザーを問いません。`user` と `repository` は変えません。実現する利用場面は、「同じブランチを、複数のマシンや OS のセッションで扱う」と「同じリポジトリで並行する複数の作業の連絡を、作業ごとに分ける」の 2 つです。ブランチのスコープは、チャットとメモリの両方で使えます。自分が申告していないブランチの内容を読む手段は、設けません。書き込みの既定、読む操作の既定、ルーム、他のユーザーの宛先、受信者が決まる時点、メモリの操作の権限、メモリの上限と忘却、申告の値の扱い、管理コマンドと書き出し、スコープを報告する順は、今の `repository` のスコープの規則を当てはめます (`session list` には、ブランチの列を末尾に足します)。

## LADR-004 ブランチの申告と追従

決定者: Tetsuo Honda  
最終更新日: 2026-11-22

### 背景と課題

サーバーは、エージェントのマシンの状態を調べられません。ブランチの名前をどのコマンドで調べて申告するか、名前が得られないときの扱い、大文字と小文字、`lounge_join` の呼び直しでの置き換え、ブランチの切り替えへの追従を決める必要がありました。

### 得られた事実

- `git branch --show-current` は、ブランチにいるときにローカルの名前を、作業ツリーの中ではその作業ツリーのブランチを、ブランチにいないとき (detached HEAD) に空の出力 (終了コード 0) を返します。Git の管理下でないフォルダーでは、エラー (終了コード 128) です (Git 2.56.0、Linux x86_64 (WSL 2)、一時フォルダーのリポジトリで確認)。
- 今の規則では、origin とマシンの名前は小文字にそろえ、`origin` と `folder` は 1 組で置き換えます (`internal/profile/profile.go`、`internal/tools/lounge.go` の `joinParams`)。
- 今の使い方の案内は、作業するリポジトリまたはフォルダーが変わったら、同じ名前で `lounge_join` を呼び直すとしています (`internal/tools/help.go`)。
- Windows と macOS で、ブランチの名前の大文字と小文字が打ち込んだとおりに表示される動作は、確認していません。

### 決定

エージェントは、`git branch --show-current` の出力 (ローカルのブランチの名前) を、`lounge_join` の `branch` に渡します。ブランチを申告していないセッションと、リポジトリの単位が空のセッションは、ブランチのスコープを使えず、エラーで案内を受けます。ブランチの名前は、小文字にそろえて比べます。`origin`、`folder`、`wsl_distro` のどれかを渡した呼び出しでは、ブランチも置き換え (`branch` を省くと空)、`branch` だけを渡した呼び出しでは、ブランチだけを置き換えます。ブランチを切り替えたときは、エージェントが同じ名前で `lounge_join` を呼び直します (案内に書きます)。サーバーの仕組みは足しません。

## LADR-005 識別子と一覧での表示

決定者: Tetsuo Honda  
最終更新日: 2026-11-22

### 背景と課題

ブランチの範囲は、リポジトリの単位とブランチの名前の 2 つで決まります。これを識別子にどう表すか、`lounge_who` でどのセッションのブランチを表示するかを決める必要がありました。

### 得られた事実

- サーバーは、識別子を分解せず、等しいかどうかだけを比べます (`internal/store/scope.go` の `SharedScopes`)。
- Git は、ブランチの名前に `:`、空白、`~`、`^`、`?`、`*`、`[`、`\` を許しません。`@` と `#` は許します (`git check-ref-format --branch` で確認。Git 2.56.0)。
- リポジトリの単位は、origin のないフォルダーでは `host-a:c:\work\app` の形で、`:` と `\` を含みます (`internal/profile/profile.go` の `Repository`)。
- `lounge_who` は、一覧に載るすべてのセッションについて、リポジトリの単位を表示します (`internal/tools/lounge.go` の `WhoSession`)。

### 決定

ブランチのスコープの識別子は、`<リポジトリの単位>:<ブランチ>` です (例: `github.com/owner/repo:feature/x`)。サーバーは、Git がブランチの名前に許さない文字を含む値を、`lounge_join` のエラーにします。`lounge_who` は、一覧に載るすべてのセッションについて、ブランチを表示します。

## LADR-006 使い方の案内文の上限

最終更新日: 2026-11-22

最終更新日: 2026-11-22

### 背景と課題

作業ブランチと、`main` へのマージの時点を決める必要がありました。前の案件での選択は、前の案件についてのものでした。

### 得られた事実

- この案件の記録と、前の案件の記録の `docs/prompts/past/` への移動は、`main` の作業ツリーにあり、コミットしていません (2026-11-22 09:46 の時点)。

### 決定

最終仕様の承認 (第 2 ゲート) の後に、作業ブランチ `feature/branch-scope` を `main` から作り、作業前の記録を最初のコミットにします。作業の途中で、作業ブランチを GitHub に push します。成果物の承認 (第 3 ゲート) を受けたら、`main` にマージして push し、作業ブランチを消します。

## LADR-009 作業の割り当て
