## BL-047 MCP を直接使わないエージェントのための CLI の方式

### 概要と問題点

- **現状の事象**: エージェントは、MCP のクライアントとしてサーバーに接続しなければ、ツールを使えません。組織の方針やエージェントの設定で MCP サーバーの登録が禁止されている場合や、MCP に対応しないエージェントとスクリプトは、シェルのコマンドを実行できても、チャットとメモリを使えません。また、参加 (`lounge_join`) は MCP の接続に結び付きます (`internal/tools/presence.go`)。このため、コマンドを 1 回実行するたびに接続して切る単純な CLI では、呼び出しのたびに参加が外れ、`chat_inbox` などが使えません。
- **本来あるべき姿**: エージェントがシェルのコマンドだけで、MCP で登録した場合と同じツールを呼べます。エージェントは MCP のプロトコルを直接扱わず、エージェント - CLI - MCP の構成で、CLI の側が MCP の接続を持ちます。

### 経緯と見送り理由

- **摘出契機**: 利用者の指示で追加しました (2026-11-22)。
- **今回の見送り理由**: 着手前の要望として、残課題に記録しました。検討と実装は、別の作業として開始します。

### 影響範囲とリスク

- **影響対象**: `cmd/agent-lounge-mcp/` (新しいサブコマンド)、MCP のクライアントの部分 (新規。Go SDK のクライアントを使う想定)、`lounge_help` の文面 (CLI の呼び出し方)、`docs/ja/user-guide.md` と `docs/ja/reference.md`、検証の基盤 (`scripts/interactive/`)。サーバーの側は、変えずに済む見込みです (CLI の側の常駐するプロセスが、通常の MCP のクライアントとして接続するため)。
- **放置した場合のリスク**: MCP サーバーを登録できない環境のエージェントが、ほかのエージェントと会話とメモリを共有できません。

### 推奨される対応策

- **恒久対応案**: host-shell-mcp の `host-shell session` と `host-shell call` (同リポジトリの `docs/ja/cli-without-mcp.md`) と同じ構成にします。次の 3 つで構成します。
  - ローカルに常駐するセッションのプロセス (例: `agent-lounge-mcp session start [--detach] --url URL`): サーバーへの MCP の接続 (Streamable HTTP) を 1 本持ち続けます。参加は、この接続に結び付くため、CLI の呼び出しをまたいで保たれます。
  - CLI (例: `agent-lounge-mcp call TOOL KEY=VALUE ...`、`agent-lounge-mcp tools`): 呼び出しのたびに、Unix ドメインソケット (Windows では名前付きパイプ、または同等の手段) でセッションのプロセスにつなぎ、ツールを 1 回呼んで、結果の JSON を標準出力に出して終わります。引数の渡し方 (`KEY=VALUE`、`KEY=@FILE`、`--json -`)、終了コード、`--session` による複数セッションの選択は、host-shell に揃えます。
  - 終了 (`session stop`、`status`、`list`)。
- **設計で決める点**: (1) トークンの渡し方 (セッションの起動時だけに受け取り、CLI の引数と履歴に残さない。BL-031 の (4) と (5) と関係します)。(2) `--connection-idle` で接続が閉じられた場合と、サーバーの起動し直しの場合の、セッションのプロセスによる接続し直しと、参加のし直し (同じ名前での `lounge_join`)。(3) `chat_inbox` の `wait_seconds` と、エージェントのシェルの時間の制限の関係 (待ちの途中で CLI が中断された場合の扱い)。(4) 参加時のプロフィール (Git の origin、フォルダー) を、セッションのプロセスと CLI のどちらの作業フォルダーから取るか。(5) エージェントのシェルが、コマンドの終わりにその子プロセスを終わらせる場合 (Codex のサンドボックスなど)、`--detach` のセッションが残らない制限。(6) 組織の方針が MCP を禁止している場合に、この方式が方針に反しうることの文書での注意。
