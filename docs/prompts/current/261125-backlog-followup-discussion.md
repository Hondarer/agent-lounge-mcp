- **分かったこと (Windows 担当の報告。Codex 0.172.0)**:
    - Codex は、`PATH` で最初に見つかる `pwsh` を使い、なければ `powershell.exe` (Windows PowerShell 5.1) を使って、どのコマンドも `<シェル> -Command '<コマンド>'` で包んで起動します。シェルのパスを選ぶ設定の項目は、手元の資料と実行ファイルからは見つかりませんでした (`--enable powershell_shell_version` は効果なし)。
    - この機械の `pwsh` は Microsoft Store 版で、`WindowsApps` の下の実行エイリアス (リパース ポイント `IO_REPARSE_TAG_APPEXECLINK`) です。サンドボックスの中では、これを起動できません (`CreateProcessAsUserW failed: 5`)。`-s read-only` でも `-s workspace-write` でも同じです。
    - その実行だけ `PATH` から `WindowsApps` を外すと、Codex は `powershell.exe` 5.1 を使い、プロセスの作成に成功しました。この構成で、3 回とも `repository` と `branch` を申告しました。
    - ただし `hostname` は、この機械の `PATH` で Git for Windows の `usr\bin\hostname.exe` (MSYS2) が `System32` のものより先にあり、サンドボックスの中で失敗しました (`machine` は渡せていない見込み)。
    - インストーラー版の PowerShell 7 はこの機械になく、その場合に起きないかは確かめていません。
- **各案の違い**:
    - A: 使い方の案内 (`help.go`) は変えません (エージェントの側では `PATH` を変えられないため)。利用ガイドの検証済みの範囲と、Codex の利用の注意に、「Windows の Codex のサンドボックスは、Microsoft Store 版の PowerShell 7 (実行エイリアス) を起動できず、シェルのコマンドがすべて失敗し、プロフィールが空になる。インストーラー版の PowerShell 7 を使うか、Codex を起動するときの `PATH` から `WindowsApps` を外す (Windows PowerShell 5.1 が使われる)」ことを書きます。`hostname` の件は、Git for Windows の `usr\bin` を `PATH` に入れている環境の注意として書きます。インストーラー版の PowerShell 7 での確認と、Codex の開発元への報告は、残課題に残します。
    - B: A に加えて、Codex の開発元への報告の文面 (英語) も、この案件で作ります (送るのは利用者)。
    - C: 文書には書かず、結果を確認の記録に残すだけにします。
