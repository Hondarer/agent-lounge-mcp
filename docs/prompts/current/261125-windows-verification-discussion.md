### Q-002 Windows 向けの実行ファイルの用意

**Status**

解決済み

**Question**

Windows の確認に使う実行ファイルを、どこでビルドしますか。

**Context**

- **経緯と背景**: これまでの Windows の確認では、Windows の側に Go がなかったため、サーバーを WSL の側で動かすか、WSL でクロス コンパイルした実行ファイルを使いました。今は、Windows の側に Go 1.27.4 があります。
- **各案の違い**:
    - A: Windows 担当が、Windows の作業フォルダーの `main` (同じコミット) で `go build` します。Windows でのビルドも同時に確かめられ、ファイルの受け渡しが要りません。
    - B: WSL の側で `make dist` の `windows-amd64` をビルドし、Windows のフォルダー (`/mnt/d/...`) へコピーします。配布物と同じ作り方になります。
- どちらも、ビルドした実行ファイルはリポジトリの外 (Windows の一時フォルダーなど) に置き、確認用のデータベースも一時フォルダーに置きます。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) Windows 担当が、Windows の側で同じコミットからビルドする
- [ ] B: WSL の側でクロス コンパイルして、Windows のフォルダーへコピーする
- [ ] C: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

回答者: Tetsuo Honda  
回答日時: 2026-11-25 19:20 JST (記入の連絡を受けた時刻)

**Recommendation**

推奨: A  
優先した基準: 手順の少なさと、Windows での実際の使い方に近いことを優先しました。  
理由: 利用者が Windows で使う場合も、Windows でビルドするか配布物を使います。A では、WSL から Windows のフォルダーへの書き込みが要りません。配布物そのものの確認を重視する場合は、B を選んでください。

- [ ] B: Windows 担当も、確認の記録を書いてコミットする
- [ ] C: その他
