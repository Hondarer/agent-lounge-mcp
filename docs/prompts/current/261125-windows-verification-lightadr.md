## LADR-001 案件の対象

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

利用者が Windows の側に agent-lounge-mcp 用の Claude Code のセッションを用意しました。残課題一覧 `261124-help-text-result-backlog.md` の 13 件のうち、この環境で進められる項目を選ぶ必要がありました。

### 得られた事実

- Windows の側のセッションとの疎通を確かめました (2026-11-25 19:16)。Windows の側には Go 1.27.4 と 5 つの CLI があります。
- Grok は、WSL の側で利用の上限のままです (`402 Payment Required`、2026-11-25 19:14 に確認)。
- Go SDK の最新は、v1.9.0-pre.1 のままです (`go list -m -versions`)。

### 決定

この案件では、次の 7 つを確かめます。BL-014 (Windows の日本語の名前と書き出し)、BL-044 (Windows のブランチのスコープ d から f)、BL-047 の (1) (Windows の CLI の方式) と (2) (Codex のサンドボックスの `--detach`)、BL-042 (Windows の Codex の作業中の表示)、BL-040 (agy の新しい版での確かめ直し)、BL-048 (`shared` とルームを、Codex、Copilot CLI、agy で)。BL-028 と、他の 6 件 (BL-013、BL-030、BL-031、BL-035、BL-036、BL-050) は、対象外です。

## LADR-002 Windows 向けの実行ファイル

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

Windows の確認に使う実行ファイルを、どこでビルドするかを決める必要がありました。

### 得られた事実

- Windows の側に、Go 1.27.4 (windows/amd64) があります。Windows の作業フォルダーは、WSL の側と同じ `main` の `d7959b6` です。

### 決定

Windows 担当が、Windows の作業フォルダーの、WSL の側と同じコミットから、Windows の側で実行ファイルをビルドします。実行ファイルと確認用のデータは、リポジトリの外に置きます。

## LADR-003 2 つのセッションの役割

## LADR-004 確かめる CLI の版と利用の上限

決定者: Tetsuo Honda  
最終更新日: 2026-11-25

### 背景と課題

Windows の Claude Code の版が WSL の側と違います。また、CLI が利用の上限に達した場合の扱いを決める必要がありました。

### 得られた事実

- Windows の側は Claude Code 2.1.330、WSL の側は 2.1.331 です。
- 前の案件 `help-text-result` では、利用者の指示 (「トークンリミットの場合は未検証としてください。」) で、Grok を未検証にしました。

### 決定

- CLI は、今の版のまま確かめ、その版を記録します (Windows の Claude Code は 2.1.330)。
- 利用の上限に達した CLI の確認は、未検証として記録し、残課題一覧に残して先へ進みます。
