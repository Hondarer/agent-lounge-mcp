### 調査で確認した事実

ユーザーが明示した内容は、次のとおりです (対話での指示)。

- 前の案件の成果物を承認し、`main` にマージして、次の案件を開始します。
- 残課題は、その都度、全量を引き継ぎます (以前の案件での指示)。
- リポジトリの空間は、複数のユーザーで同じリポジトリを扱う際に、マシン、ユーザー、OS をまたいで協調させることを目的とし、別のリポジトリと混ざらないことも要件です (前の案件の Q-011 の補足)。

現在の実装で確認したことは、次のとおりです。

- 認証はありません。すべての接続を、固定のユーザー `local` として扱います。`users` テーブルには、名前とトークンのハッシュ値の列があり、`local` には、どのトークンとも一致しない値を入れています。
- `--listen` にループバック以外を指定すると、「トークン認証を実装するまでは、ループバックだけ」という理由で、起動を中止します (`internal/config/config.go`)。
- `/mcp` は、`Host` ヘッダーがループバック以外を指す要求を、状態コード 403 で拒否します。ブラウザーからの、別のオリジンの要求も拒否します。
- セッション名は、ユーザーごとに一意です (`sessions` の一意の制約は、ユーザーと名前の組)。
- リポジトリのルーム宛ての送信は、ユーザーを問わず、同じリポジトリの単位のセッションに届きます (実装済み。ユーザーが 1 人のため、違いは現れていません)。
- `lounge_who` は、同じユーザーのセッションだけを一覧します。`chat_send` の `to` は、同じユーザーのセッションだけを指します。
- 本文の大きさと件数に、サーバー独自の上限はありません (HTTP の要求は 4[MiB] まで)。

このマシンで確認したことは、次のとおりです。

- WSL 2 は、ホストの Windows と別のアドレス (`eth0` に、プライベートのアドレス) を持ちます。Windows の側から WSL の `127.0.0.1:7788` へは、WSL の転送の機能で届きます (前の案件で確認)。
- Windows の側の Claude Code のセッションに、セッション間のメッセージで操作を依頼できます。Windows の側には、5 つの CLI があります (前の案件で確認)。
