**Question**

**Context**

- **今の動作**: Codex 以外の 4 つの CLI は、まず 2026-07-28 で `server/discover` を送ります。今の Go SDK (v1.8.0) の状態を持つ受け口は、`server/discover` に、古い版だけ (`2025-11-25`、`2025-06-18`、`2025-03-26`、`2024-11-05`) を答えます。他の 2026-07-28 の要求には、対応する版を添えたエラー (`-32022`) を返します。CLI は、その答えで 2025-11-25 の初期化に切り替えます。SDK の文書は、この動作を「クライアントが古い版で接続し直せるようにするもの」と説明しています。
- **使われない接続**: 確認用のフォルダーで、Claude Code (2.1.328) を接続させました。2026-07-28 の 1 つ目の接続は、要求の間だけの一時的なもので、サーバーに残りませんでした (停止のときの接続の一覧に現れない)。BL-036 の「接続のたびに、使われない接続が 1 つできる」は、メモリに残り続けるものではありません。

- **CLI の側**: SDK のクライアントは、サーバーが新しい版に対応しない場合、古い版に切り替えます。仕様の上でも、古いサーバーへの切り替えは、クライアントの通常の動作です。

### Q-005 使われなくなった接続の扱い

**Status**

解決済み

**Question**

クライアントが閉じずに終了した MCP の接続がサーバーに残り続ける問題 (BL-039) を、この案件で扱いますか。

**Context**

- **事象**: Q-003 の確認で判明しました。サーバーは、SDK の `SessionTimeout` を設定していません (値が 0 のとき、使われない接続を閉じません)。Claude Code (2.1.328) の非対話の実行が終わった後も、接続がサーバーに残り、サーバーの停止は、停止の待ち時間 (5[秒]) の終わりまで待ちました。参加した接続は、接続の終わりを待つ処理も 1 つずつ持ちます。
- **影響**: 長く動かすサーバーで、CLI の実行のたびに接続が増え、メモリの使用量が増え続けます。停止に、毎回、停止の待ち時間がかかります。
- **直す場合の懸念**: 一定の時間で接続を閉じると、長く指示を待っていたエージェントの次の呼び出しは、無効になった接続 (HTTP の 404) に送られます。仕様では、クライアントは接続し直します。CLI が接続し直さない場合、エージェントは、CLI を起動し直すまでサーバーを使えなくなります。5 つの CLI の動作は、確かめていません。
- 扱う場合は、まず検証の基盤で 5 つの CLI の動作を確かめ、すべてが接続し直す場合にだけ設定します。閉じるまでの時間は、確かめた結果を見て、別の Q で決めます。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) この案件で扱う。5 つの CLI が、無効になった接続の後に接続し直すかを確かめ、すべてが接続し直す場合に、使われない接続を閉じる設定を加える。接続し直さない CLI がある場合は、結果を記録して残課題にする。
