## 基盤で見つけた問題と対処

確認の途中で、基盤が CLI を操作できない問題を見つけて直しました。

| 番号 | 事象 | 対処 |
| --- | --- | --- |
| 1 | 変わった部分だけを描き直す CLI (Copilot CLI) で、完了の語が、制御文字で分かれて届く | 端末の画面を再現する処理を加えた。完了の語を大文字にして、指示の表示と区別した |
| 2 | 準備ができない CLI が動いたままになり、Windows で作業フォルダーを削除できない | 例外を返す前に、CLI を終了する |
| 3 | Grok が、2 つ目の確認の画面 (フォルダーを信頼するか) で止まる | 確認の画面への応答を加えた |
| 4 | agy が、ツールの許可を求める画面で止まる | 許可の設定ファイルを、起動のたびに書いて渡す |
| 5 | Copilot CLI のモデルが、「合言葉」を答えるのを断る | 問いを、プロジェクトの「呼び名」を答える形にした。答えがない場合は、新しいセッションで 1 回やり直す |
| 6 | Windows で、Codex の起動のオプションの引用符が、`.cmd` の起動スクリプトを通ると崩れる | 値を引用符なしで渡す |
| 7 | CLI に渡す `PWD` が、基盤のフォルダーのままで、Copilot CLI が、フォルダーの許可の画面で止まる | `PWD` を、CLI の作業フォルダーにする |
| 8 | Codex が、起動の直後の入力を落とす (WSL で 3 回に 1 回ほど)。Windows では、送信のキーが効かない | 入力が画面に出たことを確かめてから送信する。画面が 3[秒] 動かなければ、送信のキーを送り直す |
| 9 | Claude Code 2.1.327 が、Claude Code のセッションの作業用の一時フォルダーの下の `CLAUDE.md` を読まない | 確認用のフォルダーを、その外に置く (文書の制限事項に書いた) |
| 10 | Copilot CLI が、プロフィールの値を調べるシェルのコマンドの許可の画面で止まる (モデルが、実行のたびに違うコマンドを選ぶ) | シェルのコマンドをすべて許可する (`--allow-tool shell`) |

Table: 基盤で見つけた問題と対処

10 番の許可は、確認用のフォルダーの中に限定されません。Copilot CLI は、基盤を実行したユーザーの権限で、任意のコマンドを実行できます。先に、コマンドを個別に許可する方法を試し、足りなかったため、広い許可に変えました。Windows の側では、Windows の側のセッションが、この点を利用者に伝えて、承認を受けてから実行しました。

7 番を直す前の WSL の側の実行では、エージェントが申告するフォルダーの値が、作業フォルダーではない可能性があります。この記録の値は、直した後の実行のものです。

## 実装のレビュー

コミット `a83a0ce` を、このセッションと同じモデルのサブエージェントがレビューしました (ファイルを変更しない条件)。指摘と対処は、次のとおりです。

| 指摘 | 区分 | 対処 |
| --- | --- | --- |
| 接続の診断が、クライアントの設定したレベルが `warning` より上の場合にも、`shutdown notice sent` と書く (実際には送られない) | 不具合 | レベルを比べて、`not sent (the log level <レベル> is above warning)` と書く。自動テストとリファレンスに追加 |
| リファレンスが、接続の診断の行に日時が付くと書いている (実際には付かない) | 文書の相違 | リファレンスと、基盤のコメント、自己試験のデータを直した |
| プロトコルの版 2026-07-28 を試してから接続し直すクライアントが、2 つの番号の行になることが、文書にない | 文書の相違 | リファレンスに書いた |
| 長い要求の処理中に接続がなくなると、別の番号で、もう一度クライアントの行が書かれる可能性 | 軽微 (未確認) | 接続の状態を、要求の処理の前に取得する形にした |
| クライアントの名前の、文字の向きを変える文字などが、そのまま出力される | 軽微 | 書式の制御の文字を除く。自動テストを追加 |
| 基盤が、同じアドレスで応答する別のサーバーを、起動したサーバーと取り違える | 不具合 | 起動の前に、アドレスが応答しないことを確かめる |
| シナリオ 6 で、登録のコマンドが時間切れになると、トークンを含むコマンドの文字列が、結果のファイルに残る | 不具合 | 結果の理由と、例外の記録から、トークンを置き換える |
| サーバーの停止や、登録の確認が例外を返すと、結果が書かれず、他のサーバーが止まらない | 不具合 | 停止を 1 つずつ保護し、結果を先に書く。登録の一覧を取得できない CLI は、登録を変えずに飛ばす |
| シナリオ 2 と 3 が、応答の時間切れを「不合格」と記録する | 最終仕様との相違 | 合格の条件を満たさず、応答も終わらない場合は、`unverified` にした |
| シナリオ 5 が、`notes.txt` が作られなかった実行を、「受信箱を確かめなかった」と数える | 不具合 | 区別できない実行は `null` にし、回数に数えない。区別できた実行の数を記録する |
| シナリオ 6 が、有効なトークンで参加できなかった場合にも、結果を記録する | 不具合 | `unverified` にした |
| シナリオ 1 の「モデルに伝わったか」の判定に、画面の描き直しが混ざる | 判定の誤りの可能性 | 応答で増えた行だけで判定する |
| 仮想端末の出力の、複数バイトの文字が、読み取りの境目で壊れる | 不具合 | 続きを待つ復号にした |
| 長い制御の列 (リンクなど) が、読み取りの境目で分かれると、画面に文字として出る | 不具合 | 待つ長さを広げた。自己試験を追加 |
| 送信のキーの後の出力を、見逃す場合がある | 不具合 | 出力の位置を、キーを送る前に記録する |
| CLI が終了した後に残った子プロセスが、終了されない。仮想端末の作成に失敗すると、ファイル記述子が残る | 軽微 | プロセスのグループを必ず終了する。失敗のときに閉じる |
| `chat-probe.sh` の最後の処理が、未読が 100 件を超えるセッションで、未読を残したまま成功と表示する | 軽微 | 受信箱が空になるまで繰り返す |
| 文書と実装の相違 (利用ガイドに `--log-connections` の案内がない、`__pycache__`、`connections` の対象のシナリオ、`server.log` の場所、`--goarch`、CLI の定義の指示ファイル) | 文書の相違 | 文書と定義を直した |

対処しなかった指摘は、残課題一覧に記録しました (基盤の、指示の打ち直しのときに入力欄を消さないこと、端末の画面の再現の細かな相違、Windows での時間切れのときの子プロセス、出力の検索の速さ、応答の完了の判定の待ち時間、トークンを探す場所の範囲)。

修正の後、自己試験 (17 件)、`go test -race ./...`、`chat-probe.sh` の 2 回の実行、WSL の側の Codex のシナリオ 1、2、6 を実行し、結果が変わらないことを確かめました。Windows の側では、修正の後の基盤を実行していません。

## 最終仕様との相違

実装の途中で、最終仕様と変えた点です。

| 最終仕様 | 実装 | 理由 |
| --- | --- | --- |
| 端末エミュレーターは使わず、制御文字を除いた文字列で判定する | 端末の画面を再現する処理を、基盤の中に持つ | 変わった部分だけを描き直す CLI では、制御文字を除いた文字列に、応答の語がつながって現れないため |
| 完了の目印を、2 つの部分に分けて示す | 小文字で示し、大文字で書かせる | 上と同じ理由で、分けた部分の間に、他の文字が入るため |
| 接続の診断に、`notifications/initialized` を書く | 通知は書かない | クライアントの行を、初期化の後に 1 回書くため、不要 |
| モデルの名前が分かる場合は、記録する | 記録しない | CLI から、共通の方法で取得できないため |
