# `lounge_help` の案内をテキストだけで返す 成果物実装前の検討

ファイル名: `261124-help-text-result-discussion.md`

## 明確化のための確認項目

### Q-001 直し方

**Status**

解決済み

**Question**

Claude Code 2.1.331 が `lounge_help` の案内を読めるようにするため、`lounge_help` の結果の形をどう変えますか。

**Context**

- **経緯と背景**: 残課題 BL-049 です。Claude Code 2.1.331 は、`lounge_help` の結果を `{}` として扱い、案内の本文を読めません。
- **確かめた事実** (この検討のための確認。Claude Code 2.1.331 の `claude -p --output-format stream-json --verbose` の記録で、モデルに渡った `tool_result` を見た):
    - 今の `lounge_help` は、テキストの結果に案内の本文 (19,222 バイト) を、構造化された結果 (`structuredContent`) に `{}` を返します。Claude Code がモデルに渡したのは `"content": "{}"` だけでした。Claude Code は、構造化された結果があると、テキストの結果ではなく、それをモデルに渡します。
    - 出力スキーマを持たず、構造化された結果を返さない形の試作 (`lounge_help` だけを変えた、一時的なビルド) では、Claude Code がモデルに案内の本文を渡しました (19,534 文字の `tool_result`)。
    - 参加の後は、構造化された結果が `{"unread":0}` などになります (コードの読み取り。`HelpOutput` が `unread` を持つ)。この場合も、Claude Code は本文を渡さないと考えられます。CLI の方式の `call` も、構造化された結果が `{}` でなければそれを出すため、参加の後の `lounge_help` で本文ではなく `{"unread":0}` を出すと考えられます (`internal/loungecli/cli.go` の `result`。コードの読み取り)。
- **前の決定**: 案件 `connection-guidance` の LADR-008 で、Copilot CLI がテキストと構造化された結果の両方を受け取り、案内が 2 回分の大きさになって一度に読めなかったため、構造化された結果から本文を外しました。上限 `maxGuideBytes` (19,300 バイト) は、Copilot CLI 1.0.114 が一度に読める大きさに基づきます。
- **各案の違い**:

| 案 | 形 | Claude Code | Copilot CLI (両方を受け取る) | 他のツール |
| --- | --- | --- | --- | --- |
| A | `lounge_help` だけ出力スキーマを持たず、テキストの結果だけを返す。参加の後は、今と同じく最後の行に未読の件数の行を付ける | 本文を読める (試作で確認) | 今と同じ大きさ | 変えない |
| B | 構造化された結果に本文を入れる (`guide`) | 本文を読める | 2 回分 (約 38KB) になり、一度に読めない | 変えない |
| C | B に加え、本文を半分 (約 9,600 バイト) に縮める | 本文を読める | 一度に読める | 変えない。ただし、案内する規則を大きく減らす |

**Answer**

選択方式: 単一選択

- [x] A: (推奨) `lounge_help` だけ、出力スキーマを持たず、テキストの結果だけを返す。
- [ ] B: 構造化された結果に本文を入れる。
- [ ] C: 構造化された結果に本文を入れ、本文を半分に縮める。
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

回答者: Tetsuo Honda  
回答日時: 2026-11-25 06:50 JST (記入の連絡を受けた時刻)

**Recommendation**

推奨: A  
優先した基準: どの CLI でも案内の全文を読めること、前の決定 (Copilot CLI の大きさの制約) との整合。  
理由: A は、Claude Code の試作で本文が渡ることを確かめました。Copilot CLI など、テキストを読む CLI には、今と同じ本文だけが渡ります。参加の後の `call` の出力の問題も、同時に解消します。`lounge_help` の結果の `unread` の項目はなくなりますが、未読の件数はテキストの最後の行で伝わります。B は Copilot CLI で読めなくなり、C は案内の規則を大きく減らします。

### Q-002 確認の方法

**Status**

解決済み

**Question**

直した後の確認を、どの CLI で行いますか。

**Context**

- **経緯と背景**: 直し方によっては、すべての CLI に渡る `lounge_help` の結果が変わります (Q-001 の A では、出力スキーマと構造化された結果がなくなる)。
- **使える CLI**: Claude Code 2.1.331、Codex 0.171.0、Copilot CLI 1.0.114、Grok 1.0.92、agy 1.5.15 (いずれもこの WSL の環境)。
- **確かめ方**: CLI に `lounge_help` を呼ばせ、受け取った本文の先頭と末尾 (末尾の貼り付け用の例) を答えさせます。Claude Code は、加えて、モデルに渡った結果を `stream-json` の記録で確かめます。Copilot CLI は、一時ファイルに保存せずに読んだかを、出力で確かめます。
- **各案の違い**: A は、結果の形が変わる影響を全 CLI で確かめます。B は、問題の起きた Claude Code と、大きさの制約がある Copilot CLI だけを確かめ、他の 3 つは残課題にします。

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 5 つの CLI で確かめる。
- [ ] B: Claude Code と Copilot CLI で確かめ、他の 3 つは未検証として残課題にする。
- [ ] C: Claude Code だけで確かめる。
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足: トークンリミットの場合は未検証としてください。

回答者: Tetsuo Honda  
回答日時: 2026-11-25 06:50 JST (記入の連絡を受けた時刻)

**Recommendation**

推奨: A
