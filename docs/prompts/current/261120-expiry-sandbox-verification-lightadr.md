## LADR-003 確かめる未検証の項目と方法

決定者: Tetsuo Honda  
最終更新日: 2026-11-20

### 背景と課題

未検証の項目のうち、この案件で確かめる項目と、その方法を決める必要がありました。

### 得られた事実

- 文書の「検証済みの範囲」と残課題一覧から、この環境と Windows の側のセッションで確かめられる見込みのある項目は、10 件です (検討用 Markdown の Q-002 の a から j)。
- Windows の側のセッションは、応答します。WSL のネットワークは NAT のモードで、Windows のファイアウォールは有効です。新しい実行ファイルがループバック以外で待ち受けると、受信の許可を求める画面が出る見込みです (Windows の側のセッションの調査)。
- Windows の Claude Code と Copilot CLI は、PowerShell を使っていました。Claude Code は、`CLAUDE_CODE_GIT_BASH_PATH` で Git Bash を使えます。`cmd` を使う CLI は、見つかっていません。
- 検証の基盤は、Windows では疑似端末 (ConPTY) にキーを送ります。Ctrl+C の文字は、コンソールが信号に変えます。
- WSL に nginx は入っていません。podman があります。

### 決定

次の 10 項目を確かめます。結果が未検証のまま、または制限ありになった項目は、文書と残課題一覧に書きます。

- a: Windows の、origin のあるリポジトリのフォルダーでの、Claude Code 以外の 4 つの CLI の申告。
- b: Windows の側で起動したサーバーでの、期限切れと削除、管理コマンド (`session`、`export`、`memory`)。
- c: Windows の側で起動したサーバーへの、WSL の側のエージェントからの接続。この案件では確かめず、残課題に残します。
- d: 5 つの CLI が使うシェルを確かめます。Git Bash は、Claude Code に使わせて申告を確かめます。`cmd` は、使う CLI があれば確かめ、なければ文書の状況を `-` にします。
- e: Windows での Ctrl+C と 2 回目の Ctrl+C。検証の基盤の疑似端末でサーバーを起動し、キーを送って確かめます。文書には、方法を「疑似端末へのキー入力」と書きます。
- f: nginx 経由の HTTPS。podman で nginx の公式のイメージを取得し、`probe.sh`、`chat-probe.sh`、Claude Code 1 つで確かめます。確認の後、コンテナーは消し、イメージは残します。
- g: Windows の Codex と Copilot CLI の作業中の表示、Windows での Ctrl+U。
- h: 検証の基盤の直し (BL-035 の (14)、(15)、(16))。(16) の直しは、Copilot CLI のシナリオ 5 の 5 回の完了を条件にせずに取り込みます。シナリオ 5 を妨げていた Copilot CLI の別の許可の画面 (「Allow path access」) にも応答する定義を足し、5 回を流し直します。
- i: agy 1.5.13 での、閉じられた接続の後の動作の確かめ直し。
- j: フォルダーを移ったときの、Claude Code によるプロフィールの更新。

Windows の側の確認は、Windows の側のセッションに委譲します。

確認の中で見つかった、Git Bash の `pwd` が Windows のパスを返さない点 (BL-041) は、この案件で直します。`lounge_help` の Windows の行に、Git Bash では `pwd -W` を使うことを書き、Windows の側の Claude Code (Git Bash) で 1 回確かめます。

機材のない項目は、次のように扱います。`windows-arm64` と macOS は、ビルドはするが動作を保証しないこととして文書に書き、残課題から除きます。物理的に別のマシンと、WSL ではない Linux は、確かめず、残課題に残します。

## LADR-004 トークンの有効期限

決定者: Tetsuo Honda  
最終更新日: 2026-11-20

### 背景と課題

トークンに期限がなく、漏れたトークンの影響を期間で限定できませんでした (BL-031 の (1))。

### 得られた事実

- トークンは、`user rotate` で取り替えるまで有効です。データベースには、トークンのハッシュ値だけを保存しています (`internal/store/users.go`)。
- サーバーは、要求ごとにトークンを照合し、待ち受け中の `chat_inbox` は 5[秒] ごとに確かめ直します (`internal/server/auth.go`、`internal/tools/chat.go`)。
- サーバーの期間のオプションは、`14d`、`1d12h` のような形を受け付けます (`internal/config/duration.go`)。

### 決定

- 期限は、`user add` と `user rotate` の `--expires-in <期間>` で指定します。指定しない場合は、期限なしです。既存のトークンは、期限なしのままです。
- `user expiry <名前> --in <期間>` と `--never` を足します。トークンを変えずに、期限だけを変えます。
- 期限が切れたトークンには、401 と `WWW-Authenticate: Bearer error="invalid_token"` を返し、本文で、期限が切れたことと対処 (管理者に、期限の延長か発行し直しを頼む) を伝えます。
- 期限は、発行と変更のときの案内 (標準エラー) と、`user list` の末尾の列 `EXPIRES` で知らせます。エージェントへの知らせ (`lounge_join` の結果など) は、足しません。

## LADR-006 サンドボックスの中でのマシンの名前

決定者: Tetsuo Honda  
最終更新日: 2026-11-20

### 背景と課題

サンドボックスの中の Codex と agy は、WSL で `cmd.exe` を使えず、マシンの名前を申告できないため、origin のないフォルダーでリポジトリの空間を使えませんでした (BL-027)。

### 得られた事実

- Codex のサンドボックス (0.169.0。`codex sandbox`) では、`cmd.exe /c hostname` は `UtilBindVsockAnyPort ... socket failed` で失敗し、`uname -n` と `cat /etc/hostname` は、Windows のコンピューター名と同じ値を返しました。
- agy (1.5.13。許可の規則を指定した実行) では、`cmd.exe` は見つからず、`uname -n` は `sandbox`、`cat /etc/hostname` は Windows のコンピューター名と同じ値を返しました。`/mnt/c` は見えませんでした。
- WSL の既定では、Linux の側のホスト名は Windows のコンピューター名と同じです。`/etc/wsl.conf` で変えられます。
- Codex の週の利用量の残りは、15% でした (2026-11-20 08:53 の記録)。

### 決定

- 使い方の案内を変えます。WSL で `cmd.exe` が失敗する、または見つからない場合は、`machine` に `cat /etc/hostname` の出力を使い、`os_user` は省きます。
- `lounge_join` は、`machine` の値 `sandbox`、`localhost`、`localhost.localdomain` を拒否し、エラー文で `cat /etc/hostname` を使うよう伝えます。
- 実機では、Codex (`-s read-only`) と agy (許可の規則を指定した実行) で、origin のないフォルダーで参加させ、サンドボックスなしの Claude Code とリポジトリのルームで往復します (非対話の実行。各 1 回、失敗した場合は 3 回まで)。サンドボックスなしの 5 つの CLI の申告が変わらないことも、各 1 回確かめます。Codex の週の残りが 10% を切ったら、Codex の分は未検証として残します。
