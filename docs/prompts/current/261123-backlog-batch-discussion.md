### Q-004 ブランチの名前の前後の空白

**Status**

解決済み

**Question**

申告されたブランチの名前の前後にある空白を、どう扱いますか。

**Context**

- **経緯と背景**: BL-046 は、全角空白 (U+3000) を含む名前を申告できるようにする課題です。`profile.Branch` は、共通の関数 `lastLine` で最後の空でない行を取り出してから検査します。`lastLine` は `strings.TrimSpace` を使うため、全角空白も前後から取り除きます。禁止する文字の条件だけを変えると、名前の途中の全角空白は通りますが、前後の全角空白は黙って消え、別の名前のブランチと同じスコープに入ります。
- **根拠資料**: [internal/profile/profile.go](../../../internal/profile/profile.go) の `lastLine` (61 行目) と `Branch` (338 行目)。Git 2.56.0 の `git check-ref-format --branch` は、前後に全角空白のある名前と、途中に全角空白のある名前を、どちらも受理しました (Codex が一時フォルダーで確認)。
- **各案の具体例** (`␣` は ASCII の空白、`□` は全角空白):

| 申告の値 | A | B | C (今の前後の処理) |
| --- | --- | --- | --- |
| `a□b` | `a□b` | `a□b` | `a□b` |
| `□foo□` | `□foo□` | `□foo□` | `foo` |
| `␣foo␣` | エラー | `foo` | `foo` |
| `foo` + 改行 | `foo` | `foo` | `foo` |

- `lastLine` は `machine` などの他の値でも使うため、どの案でも共通の関数は変えず、ブランチの側だけで行を取り出します。

**Answer**

選択方式: 単一選択

- [ ] A: 行の終わりの改行だけを取り除き、その行をそのまま検査する。前後の全角空白は名前の一部として残し、前後の ASCII の空白はエラーにする
- [x] B: (推奨) 前後の ASCII の空白 (空白とタブ) だけを入力の余白として取り除く。前後の全角空白は名前の一部として残す
- [ ] C: 今の前後の処理を保つ (前後の Unicode の空白をすべて取り除く)。途中の全角空白だけを通す
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

その他の回答 / 補足:

回答者: Tetsuo Honda  
回答日時: 2026-11-23 09:11:55 JST (検討用 Markdown の保存の時刻)

**Assessment**

B が選ばれました。前後の ASCII の空白 (空白とタブ) だけを取り除き、前後の全角空白は名前の一部として残します。再点検: エージェントがコマンドの出力をそのまま申告し、値をそろえる処理はサーバーが行うという企画提案書の方針に合っており、変更の小ささを理由にした推奨ではありません。

**Recommendation**

推奨: B  
理由: エージェントは、コマンドの出力をそのまま渡します。出力の前後に ASCII の空白が付く場合 (シェルの引用の仕方による) を、今と同じく受け入れられます。Git は ASCII の空白を名前に許さないため、取り除いても別の名前と混ざりません。全角空白は Git が名前に許すため、残します。Codex の推奨は A (名前の同一性を最も厳密に保つ) でした。
