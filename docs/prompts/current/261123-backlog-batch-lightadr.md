## LADR-004 ブランチの名前の検査 (BL-046)

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

ブランチの名前の検査が Git の規則より厳しく、全角空白を含む名前と、`head`、`Head` という名前を申告できません。どこまで緩めるかを決める必要がありました。

### 得られた事実

- `profile.Branch` は、共通の関数 `lastLine` (`strings.TrimSpace` で前後の Unicode の空白を取り除く) を通してから検査します (`internal/profile/profile.go`)。
- Git 2.56.0 の `git check-ref-format --branch` は、全角空白を含む名前、`head`、`Head` を受理し、`HEAD` を拒否します (一時フォルダーで確認)。

### 決定

- 前後の ASCII の空白 (空白とタブ) と改行だけを取り除きます。前後と途中の全角空白は、名前の一部として残します。途中の ASCII の空白と制御文字は、今と同じく拒否します。共通の関数 `lastLine` は変えず、ブランチの側で行を取り出します。
- 元の値が `HEAD` (大文字) の場合だけ拒否します。`head` と `Head` は受け入れ、小文字の `head` として扱います。
- Git より緩い点 (`a..b`、`@{-1}` など) は、今のままにします。

## LADR-006 メッセージの一覧と書き出しの絞り込み (BL-011)

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

メッセージを一覧する管理コマンドがなく、`export` を絞り込めません。一覧の件数と、絞り込みの意味を決める必要がありました。

### 得られた事実

- 今の管理コマンドの一覧は、見出しの行が付いたタブ区切りの表です (`cmd/agent-lounge-mcp/admin.go`)。
- メッセージには、送信者、直接の宛先、送達先があります。メモリには、スコープと作成者があります (`internal/store/admin.go`)。

### 決定

- `message list` を足します。新しい順に 100 件を既定にし、`--limit N` と `--before-id ID` で続きを取れるようにします。
- `--user NAME` は、そのユーザーに関係する記録を選びます (送信者、直接の宛先、送達先のいずれかがそのユーザーのメッセージ、そのユーザーの `user` の空間のメモリ、そのユーザーが作ったメモリ)。
- `--scope KIND` に加えて、`--scope-id ID` で具体的なスコープを指定できます。

## LADR-011 セッション名とユーザー名の規則 (BL-014)

決定者: Tetsuo Honda  
最終更新日: 2026-11-23

### 背景と課題

セッション名に使える文字が英数字と 4 つの記号に限られ、日本語の役割名を使えません。使える文字の範囲と、同じ名前とみなす規則を決める必要がありました。あわせて、ユーザー名を対象にするかを決める必要がありました。

### 得られた事実

- セッション名は `^[A-Za-z0-9._@-]{1,64}$` (`internal/tools/lounge.go`)、ユーザー名は `^[a-z0-9][a-z0-9._-]{0,31}$` (`internal/store/users.go`) です。
- RFC 8265 の UsernameCasePreserved の実装が、`golang.org/x/text/secure/precis` にあります。一時フォルダーで v0.43.0 を実行し、次の動作を確認しました。`レビュー担当２` は `レビュー担当2` に、`ﾚﾋﾞｭｰ` は `レビュー` に、`Ｒｅｖｉｅｗ` は `Review` になります。`नमस्ते` と `สวัสดี` は通ります。空白、絵文字、`。`、`①`、幅のない結合子を含む名前はエラーになります。`Reviewer` と `reviewer` は別の名前のままです。ASCII の記号 (`/`、`:` など) は、この規則だけでは通ります。
- 書き出し (`export`) のファイル名は、英数字と `.`、`_`、`-` 以外の文字を `_` に置き換えます (`internal/export/export.go` の `SafeName`)。

### 決定

- セッション名は、RFC 8265 の UsernameCasePreserved の規則 (全角と半角をそろえる、NFC、文字と数字と結合記号を許す、大文字と小文字は区別する) で検査し、正規化した形で保存と照合を行います。ASCII の記号は、今の 4 つ (`.`、`_`、`-`、`@`) に限ります。長さは、正規化の後の 1 文字以上 64 文字以下です。
- ユーザー名も、同じ文字の範囲、同じ長さ (1 文字以上 64 文字以下)、同じ記号 (`.`、`_`、`-`、`@`)、先頭の文字の制限なしに広げます。ただし、大文字と小文字は、小文字にそろえます (RFC 8265 の UsernameCaseMapped)。予約の名前 `local` は、正規化の後の値で判定します。
- 書き出し (`export`) のファイル名に、Unicode の文字、数字、結合記号を残します。それ以外の文字は、今と同じく `_` に置き換え、ハッシュ値を付けます。
- 5 つの CLI が日本語の名前を引数として正しく渡すかを、WSL の実機で確かめます。Windows の側の確認は、残課題に残します。
