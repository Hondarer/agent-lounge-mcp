### Q-002 origin の相対パスの扱い

**Status**

解決済み

**Question**

origin に、方式もコロンもない相対パス (例: `foo/bar`) が渡されたとき、どう扱いますか (BL-029 の 2 番)。

**Context**

origin の正規化は、URL の形、`ユーザー@ホスト:パス` の形のほかに、正規化済みの形 (`ホスト/パス`、例: `github.com/owner/repo`) を受け付けます。正規化済みの形は、エージェントが `lounge_who` などに出る単位の値を、そのまま渡した場合に備えたものです。

一方、Git は、`git remote add origin foo/bar` のような相対パスの origin を許します。この origin は、手元の別のフォルダーを指します。今の規則は、これをホスト `foo`、パス `bar` の正規化済みの形として読み、`foo/bar` という単位にします。別のマシンで同じ相対パスを origin にしたフォルダーと、同じ単位になります。`./foo/bar` や `../foo` のように `.` で始まるものは、ローカルのパスとして origin なしになります。

ホストの名前は、ほとんどの場合 `.` を含みます (`github.com`、`gitlab.example.co.jp`)。社内の Git サーバーが `.` のない名前 (例: `gitserver`) の場合も、`git remote get-url origin` の出力は `https://gitserver/...` か `git@gitserver:...` の形で、正規化済みの形にはなりません。

| 入力 | A の結果 | B の結果 | C の結果 (今のまま) |
| --- | --- | --- | --- |
| `github.com/owner/repo` | `github.com/owner/repo` | origin なし | `github.com/owner/repo` |
| `localhost/owner/repo` | `localhost/owner/repo` | origin なし | `localhost/owner/repo` |
| `foo/bar` | origin なし | origin なし | `foo/bar` |
| `gitserver/team/repo` | origin なし | origin なし | `gitserver/team/repo` |
| `https://gitserver/team/repo` | `gitserver/team/repo` | `gitserver/team/repo` | `gitserver/team/repo` |

**Answer**

選択方式: 単一選択

- [x] A: (推奨) 正規化済みの形は、ホストの部分が `.` を含むか `localhost` のときだけ受け付ける。それ以外 (例: `foo/bar`) は、ローカルの相対パスとして origin なしにする。
- [ ] B: 正規化済みの形の受け付けをやめる。方式もコロンもない値は、すべてローカルのパスとして origin なしにする。
- [ ] C: 今のまま。制限事項に書く。
- [ ] D: その他
- [ ] X: 意図不明 (詳細な質問内容に再生成すること)

### Q-005 無効化の後の待ち受けの打ち切り方

**Status**

解決済み

**Question**

`chat_inbox` の待ち受け中に、その利用者のトークンが無効になった場合 (`user rotate`、`user remove`)、どうしますか (BL-032 の 1 番)。

**Context**

サーバーは、HTTP の要求のたびにトークンを確かめます。待ち受け中の `chat_inbox` は、1 つの要求の中で、最長で待ち受けの上限 (既定は 45[秒]) まで新着を待つため、その間にトークンが無効になっても気付きません。新着が届けば、無効になったトークンの接続が、メッセージを 1 回受け取ります。

管理コマンドは、サーバーとは別のプロセスで、データベースを直接書き換えます。サーバーに知らせる手段はありません。

`user remove` では、そのユーザーのセッションも消えるため、新着は届きません。問題になるのは、主に `user rotate` (トークンの発行し直し) です。

| 案 | 動作 | 費用 |
| --- | --- | --- |
| A | 待ち受け中、5[秒] ごとと、新着で起きたときに、要求のトークンがまだ有効かを確かめる。無効なら、待ち受けをやめ、トークンが無効になったことを伝えるエラーを返す | 待ち受け 1 件につき、5[秒] ごとに 1 回の問い合わせ |
| B | 新着で起きたときだけ確かめる。無効なら、メッセージを渡さずにエラーを返す。待ち受け自体は、上限まで続く | 新着のときに 1 回 |
| C | 今のまま。制限事項に書いてある | なし |

**Answer**

選択方式: 単一選択

- [ ] B: 新着で起きたときだけ確かめる。
