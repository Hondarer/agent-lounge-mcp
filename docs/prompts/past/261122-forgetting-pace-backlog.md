## BL-043 スコープのアクセス間隔で、忘却の進み方を緩める

### 概要と問題点

- **現状の事象**: 保持スコアは、メモリ自身の基準時刻 (更新時刻と最終参照時刻の新しいほう) からの壁時計だけで下がる。半減期は参照回数で延びる。既定値では、参照 0 回のメモリは約 23 日で薄れ、約 53 日で削除される (`internal/store/retention.go`、`docs/ja/reference.md` の「忘却モデル」)。スコープ全体が何日も使われていなくても、時計は同じ速さで進む。休止が約 53 日を超えると、参照されていないメモリは削除され、再開時の検索では見つからない。
- **本来あるべき姿**: メモリへのアクセスが半減期より短い間隔で続いているスコープでは、今の曲線のままにする。その中で古いメモリは、今までどおり先に薄れる。アクセスの間隔が半減期より長いスコープでは、空白の続きだけ忘却を遅くする。遅くする割合の下限は 1/3 とし、残る期間は今のおよそ 3 倍を超えない。再開の操作で、空白のあいだに遅らせた分が一度に戻り、スコアが落ちることはない。

アクセスの頻度は、メモリ 1 件の参照回数ではなく、スコープ (種類と識別子の組) へのメモリ操作の間隔で測る。参照回数による半減期の延長は、今の式のまま残す。

### 経緯と見送り理由

### 採用する計算

忘却を無効にする条件 (基本半減期が 0、またはしきい値が範囲外) と、固定したメモリの扱い (保持スコアは 1、薄れない、削除されない) は、今のままとする。以下は、忘却が有効で、固定されていないメモリに適用する。

記号:

- `基準時刻` は、更新時刻と最終参照時刻の新しいほう (今と同じ)。
- `半減期` は、`--memory-half-life × (1 + log2(1 + 参照回数))` (今と同じ)。
- `しきい値` は、`--memory-fade-threshold`。
- `猶予` は、`--memory-grace`。
- `W` は、基本半減期 (`--memory-half-life`)。アクセス間隔がこの長さ以下なら、そのスコープは使われているとみなす。
- `q` は、そのスコープの最終アクセス時刻から現在時刻までの壁時計の長さ。
- `有効経過` は、保持スコアに使う時間。壁時計の経過から、空白のあいだに進めなかった分を引いた値。

空白の長さ `q` のうち、忘却時計に載せる長さ `g(q)` は、次のとおり。

```text
g(q) = q                     (q <= W)
     = W + (q - W) / 3       (q > W)
```

`q <= W` では今と同じ速さ (傾き 1)。`q > W` では傾き 1/3。壁時計 1 日あたりに進む忘却は、1 日以下かつ 1/3 日以上である。長い空白ほど、壁時計に対する倍率 `q / g(q)` は 3 に近づき、3 を超えない。

スコープごとに、次の 2 つを保存する。

- `最終アクセス`: そのスコープのメモリ操作の時刻。
- `割引`: すでに閉じた空白について、壁時計のうち忘却時計に載せなかった長さの累計。

メモリごとに、次を保存する。

- `起点割引`: そのメモリの基準時刻の時点での、スコープの `割引`。

現在時刻での有効経過は、次のとおり。開いている空白の割引は、その場で計算し、アクセスがあるまで `割引` には足さない。

```text
開いている割引 = 0                 (q <= W)
               = (2/3) × (q - W)   (q > W)

有効経過 = (現在時刻 - 基準時刻) - (割引 - 起点割引) - 開いている割引
```

有効経過が 0 未満のときは 0 とする。保持スコア、薄れる時点、削除の時点は、壁時計の経過を有効経過に置き換える。

```text
保持スコア = 2 ^ ( -有効経過 / 半減期 )
薄れる     = 有効経過 >= 半減期 × log2(1 / しきい値)
削除       = 有効経過 >= 半減期 × log2(1 / しきい値) + 猶予
```

猶予も有効経過で測る。空白中は、薄れてから削除されるまでの壁時計も、同じ割合で長くなる。`--memory-grace` が 0 のときは、今と同じく削除しない。

スコープへのアクセスが起きた時刻 `T` では、同じトランザクションで、開いている空白を閉じてから、触れたメモリの基準時刻を動かす。

```text
q = T - 最終アクセス
割引 += q - g(q)          # q <= W なら 0
最終アクセス = T
```

基準時刻が `T` になるメモリ (作成、更新、参照として数えた取得、固定の解除) は、`起点割引` を、閉じたあとの `割引` にする。基準時刻が動かないメモリは、`起点割引` を変えない。閉じる前後で、それらの有効経過は同じ値になる。

薄れる壁時計の時刻は、次で求める。`払済 = 割引 - 起点割引` とする。温かい区間の終わり `最終アクセス + W` の有効経過を `Ewarm = (最終アクセス + W - 基準時刻) - 払済` とする。

```text
Ewarm >= 半減期 × log2(1 / しきい値) のとき
    薄れる時刻 = 基準時刻 + 払済 + 半減期 × log2(1 / しきい値)
それ以外のとき
    残り = 半減期 × log2(1 / しきい値) - Ewarm
    薄れる時刻 = 最終アクセス + W + 3 × 残り
```

削除の時刻は、上のしきい値までの有効経過に `猶予` を足した値で、同じ形で求める。

この式は、アクセス間隔が `W` 以下のあいだ、割引が増えない。有効経過は壁時計と一致し、今の曲線と同じになる。間隔が開いたスコープでは、開いた分だけ有効経過が遅れる。再開のアクセスは遅れた分を `割引` に移すだけで、有効経過は増えない。再開のあと、また間隔が `W` 以下でアクセスが続くあいだは、古いメモリの有効経過が壁時計と同じ速さで増える。

### アクセスとして数える操作

スコープの最終アクセスを進める操作は、エージェントがそのスコープのメモリを読んだか書いたときである。参照回数 (24 時間に 1 回、検索の上位 3 件) とは別に数える。回数の規則は変えない。

| 操作 | 最終アクセス | メモリの基準時刻と起点割引 |
| --- | --- | --- |
| `memory_put` の作成と更新 | 対象スコープを進める | そのメモリの基準時刻を今にし、起点割引を閉じたあとの割引にする |
| `memory_get` | 対象スコープを進める。24 時間の制限で参照回数を増やさない取得も含む | 参照として数えたときだけ、基準時刻と起点割引を更新する |
| `memory_search` | 検索したスコープを、件数に関係なく進める。`scope` を省いた検索は、そのセッションが使えるスコープをそれぞれ進める | 参照として数えたメモリだけ、基準時刻と起点割引を更新する |
| `memory_pin` の固定 | 対象スコープを進める | 基準時刻は変えない |
| `memory_pin` の解除 | 対象スコープを進める | 今の実装どおり最終参照時刻を解除の時刻にし、起点割引も閉じたあとの割引にする |
| `memory_forget` | 対象スコープを進める | メモリは削除する |
| 定期の削除、`export`、`memory list`、`memory remove` | 進めない | 変えない |

定期の削除や一覧が最終アクセスを進めると、静かなスコープが使われていることになる。書き出しが全スコープを走査しても、同じ理由で進めない。

検索の並び順と、結果に出す保持スコアは、その検索で参照を数える前の有効経過で計算する (今の「数える前の値」と同じ)。スコープの空白を閉じても有効経過は変わらないので、閉じたあとの値で並べてよい。

### 保存と移行

新しいスキーマのスクリプトを `internal/store/schema/` に追加する。公開済みのスクリプトは編集しない。時刻と割引の単位は、既存の列と同じミリ秒とする。

```text
memory_scope_activity (
    scope, scope_id,   -- memories と同じ組。CHECK も memories.scope と同じ値
    last_access,       -- ミリ秒
    discount,          -- ミリ秒。忘却時計に載せなかった壁時計の累計
    PRIMARY KEY (scope, scope_id)
)

memories.forgetting_credit   -- ミリ秒。基準時刻の時点の discount。既定 0
```

移行では、スコープごとに 1 行を入れる。`last_access` は、そのスコープのメモリの基準時刻の最大値 (参照がなければ更新時刻)。`discount` は 0。既存メモリの `forgetting_credit` は 0。

これにより、移行直後の開いている空白 (最後の基準時刻から移行時点まで) には、上の `g` がさかのぼって適用される。最後のアクセスから 30 日静かなスコープの、そのとき触られた参照 0 回のメモリは、有効経過 14.666667 日、保持スコア約 0.23 になり、通常の検索に残る。今の式では、同じメモリはすでに薄れている。最後のアクセスが 7 日以内のスコープは、開いている割引が 0 なので、保持スコアは移行の前後で変わらない。

すでに削除された行は戻さない。最後の基準時刻より前の空白は、スコープのアクセス時刻を個別に保存していないため、さかのぼらない。その区間は、今の式どおり壁時計で払済みとして扱う。

活動の行は、最後のメモリを削除したあとも残す。新しいメモリの起点割引は、作成時に閉じたあとの割引になるため、古い割引だけでは寿命が延びない。行が増えるだけなので、削除はこの案件の範囲に入れない。

活動の行が無いスコープは、割引 0、開いている割引 0 として、今の曲線で計算する。テストの既存の呼び出しが、スコープを渡さずに今の日数のまま通るためである。データベースから読む経路では、移行で行を作るので、この分岐には入らない。

半減期の設定を変えても、すでに閉じた `割引` は書き換えない。開いている空白の `W` だけ、新しい基本半減期を使う。

`deleteForgottenMemories` の候補抽出 (基準時刻が「参照 0 回が削除される最短」より古い行) は残せる。この変更は忘却を遅くするだけで、早くはしない。最短の削除は、使われているスコープの今の日数のままである。候補にした行は、スコープの割引を含めた有効経過で削除するか判定する。静かなスコープの行は、候補に入っても残ることがある。

基本半減期を大きくしたときの期間の飽和 (約 292 年で頭打ち) は、壁時計へ変換したあとも維持する。

### 影響範囲とリスク

- **影響対象**: `internal/store/retention.go`、`internal/store/memory.go`、`internal/store/schema/` の新しいスクリプト、`internal/store/migrate.go`、定期の削除、`memory list` の保持スコア、`cmd/agent-lounge-mcp/cleanup.go` の起動ログ、`internal/tools/help.go`、`docs/ja/reference.md`、`docs/ja/user-guide.md`。エージェントに見える変化は、保持スコア、通常の検索に出るか、削除されるまでの期間である。ツールの引数は増えない。起動オプションも増えない。
- **放置した場合のリスク**: 半減期のあいだアクセスが無いリポジトリでは、参照されていないメモリが約 23 日で通常の検索から外れ、約 53 日で削除される。
- **実装した場合のリスク**: 静かなスコープでは、古いメモリが今より長く残る。上限は今のおよそ 3 倍である。誤った内容も、同じ割合で長く残る。秘密情報の削除は、今と同じく `memory_forget` と `memory remove` で行う。使われているスコープの日数は変えない。

Git のコミットやファイルの保存は見ない。メモリのツールを呼んでいないリポジトリは、編集が続いていても静かなスコープとして扱う。再開時にメモリを残す目的には、この観測で足りる。

空間の種類 (`user` と `repository`) で半減期を変える機能は、BL-034 のまま残す。この案件が変えるのは、識別子ごとのアクセス間隔である。`user` のスコープが毎日使われていても、別のリポジトリのスコープが静かなら、そのリポジトリのメモリだけ遅くなる。

案件 `branch-scope` がスコープの種類を足すときは、`memories.scope` の CHECK と一緒に、活動の表の CHECK も新しいスクリプトで足す。

### 推奨される対応策

- **恒久対応案**: 上の計算を `internal/store/retention.go` に置く。有効経過は保存せず、読むときと削除のときに計算する (今の保持スコアと同じ)。活動の行と `forgetting_credit` だけを保存する。起動オプションは足さない。`W` は基本半減期、空白の続きの傾きは 1/3 とする。
- **利用ルール**: `lounge_help` の Forgetting に、使われているスコープは今の日数であること、半減期より長くアクセスが無いスコープは忘却が遅くなり、残る期間はおよそ 3 倍を超えないこと、を書く。既定値では、静かなスコープの参照 0 回は約 56 日で薄れ、約 146 日で削除される、と書く。
- **文書**: `docs/ja/reference.md` の「忘却モデル」と、`docs/ja/user-guide.md` の「忘却」に、同じ式と 2 つの日数の表を書く。企画提案書は、採用前の提案の記録なので、この案件では編集しない。
- **起動ログ**: `describeMemoryPolicy` に、半減期のあいだアクセスが無いスコープは、その後の忘却が 1/3 の速さになり、残る期間はおよそ 3 倍まで、と 1 行で足す。
- **テスト**:
  - `g(q)` と有効経過の単体テストが、上の表の値と一致する。
  - 活動の行が無い、またはアクセス間隔が `W` 以下のとき、既存の `TestRetentionModel` の日数 (約 23、47、70、93 日) と一致する。

  - 毎日別のメモリがアクセスされるスコープで、触られていない参照 0 回のメモリは、今と同じく 23 日目と 24 日目のあいだで薄れ、53 日目と 54 日目のあいだで削除される。

  - 版 6 のデータベースを開くと活動の行ができ、最後のアクセスが 7 日以内のスコープの保持スコアは移行前と同じである。

### 採らなかった案

- **今の周波数を、過去の経過全体の倍率にする。** 静かなあいだは約 3 倍残るが、再開してアクセスが増えた瞬間に倍率が 1 へ戻り、有効経過が壁時計まで跳ねる。休止中に残していたメモリが、最初の検索で薄れる。依頼の「再開時に残す」に合わない。
- **空白の最初から傾き 1/3 にする (`W = 0`)。** 静かなスコープの削除はちょうど 3 倍 (参照 0 回で約 160 日) になる。一方、毎日アクセスがあるスコープでも、アクセスとアクセスのあいだを 1/3 で積むと、古いメモリの寿命も約 3 倍になる。依頼の「アクセスが多いときは古いメモリが不要」に合わない。最初の半減期は傾き 1 とし、そのぶん参照 0 回の静かな場合は約 2.7 倍 (削除まで約 146 日) とする。
- **スコープの累計アクセス回数を、寿命の倍率にする。** 過去に多用されたスコープは、その後長く静かでも倍率が下がらない。頻度は、最後のアクセスからの間隔で測る。
- **Git の更新時刻をアクセスにする。** サーバーはその時刻を持たない。メモリのツール操作だけをアクセスとする。
- **アクセスが多いスコープで、今より速く忘れる。** 依頼の上限は「残す量を増やす」側であり、使われているスコープは今の曲線を維持する。
- **起動オプションで倍率や `W` を変える。** 3 倍は依頼の上限なので、傾き 1/3 と `W = 基本半減期` に固定する。基本半減期を変えた検証 (短い半減期のサーバー) では、`W` もその半減期に追従する。
