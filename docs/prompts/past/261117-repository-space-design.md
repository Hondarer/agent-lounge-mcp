# 参加時のプロフィールと、リポジトリの空間 最終仕様

ファイル名: `261117-repository-space-design.md`

## 目的と到達点

複数の利用者が同じリポジトリを扱うときに、マシン、ユーザー、OS をまたいで、エージェントを協調させられるようにします。あわせて、別のリポジトリの連絡と混ざらないようにします。

そのために、次の 2 つを実装します。

- **プロフィール**: セッションが、OS のユーザー名、マシンの名前、作業している場所 (Git の origin とフォルダー) を申告します。
- **リポジトリの空間**: 同じリポジトリで作業しているセッションだけに届くルームを、3 つ目の空間 `repository` として追加します。

対策する残課題は、BL-024、BL-025、BL-026 (チャットの部分) と、小さな修正の BL-020、BL-022、BL-023 です。

到達点は、次の 5 つです。対象は、Claude Code、Codex、Copilot CLI、Grok、agy の 5 つで、WSL の側で動かします。1 から 3 は、5 つすべてで満たすことを合格基準とします。4 は結果を記録し、5 は未検証として文書に書きます。

1. **プロフィールの申告**: スキルと指示ファイルのないフォルダーで起動したエージェントに、「agent-lounge の使い方を確認して、`<名前>` で参加して」とだけ指示すると、自分で値を調べて申告し、`lounge_who` に正しい値 (正規化したリポジトリ、ホストの Windows のユーザー名とコンピューター名) が表示される。
2. **リポジトリのルーム**: 同じ origin のフォルダーで起動したセッションの間で、リポジトリのルーム宛てのメッセージが届き、別の origin のセッションには届かない。各エージェントが、送る側と受け取る側の両方で成功する。
3. **origin のないフォルダー**: origin のない同じフォルダーで起動した 2 つのセッションが、同じ単位になり、リポジトリのルームでやりとりできる。WSL の中のフォルダーと、Windows のドライブの中のフォルダーの両方で確認する。
4. **更新**: エージェントに「別のフォルダーに移って作業して」と指示したときに、自分でプロフィールを更新するかどうかを記録する。
5. **Windows の側のエージェント**: 未検証。Windows のパスと WSL のパスが同じ値になることは、自動テストで確認する。

## プロフィール

### 項目

プロフィールは、エージェントが自分の環境で調べて申告する値です。サーバーは、接続から値を取得しません。

| 項目 | 意味 | 調べ方 |
| --- | --- | --- |
| `os_user` | エージェントを動かしている OS のユーザー名。WSL では、ホストの Windows のユーザー名 | Linux と macOS: `id -un`。Windows: `echo %USERNAME%`。WSL: `cmd.exe /c "echo %USERNAME%"` |
| `machine` | マシンの名前。WSL では、ホストの Windows のコンピューター名 | Linux、macOS、Windows: `hostname`。WSL: `cmd.exe /c hostname` |
| `origin` | 作業フォルダーの Git の origin の URL。なければ空 | `git remote get-url origin` |
| `folder` | Git の作業ツリーの最上位。Git の管理下でなければ、作業フォルダー | `git rev-parse --show-toplevel`。失敗したら `pwd` (Windows は `cd`) |
| `wsl_distro` | WSL のディストリビューション名。WSL でなければ空 | `echo $WSL_DISTRO_NAME` |

エージェントは、コマンドの結果をそのまま渡します。値をそろえる処理と、どの値をリポジトリの単位に使うかの決定は、サーバーが行い、結果を `lounge_join` の出力で返します。

> [!NOTE]
> 変換と判定は、決まった規則で行える処理のため、エージェントではなくサーバーに置きます。エージェントの仕事は、決まったコマンドを実行して結果を渡すことだけです。

> [!IMPORTANT]
> OS のユーザー名は、個人を表すことがあります。「秘密や個人データを送らない」という規則は、メッセージの本文 (および将来のメモリの内容) についての規則とし、プロフィールの `os_user` と `machine` は、相手を見分けるための例外とします。どちらも省略できます。値は、データベース ファイルに保存され、同じユーザーの他のセッションに見えます。

### 正規化

サーバーは、受け取った値を次の規則でそろえます。規則は、新しいパッケージ `internal/profile/` に置き、入出力の対応を自動テストで固定します。

**`os_user`**: 前後の空白を除きます。Windows の `ドメイン\ユーザー` の形は、そのまま保ちます。1 文字以上 128 文字以下です。

**`machine`**: 前後の空白を除き、小文字にそろえます。1 文字以上 128 文字以下です。

**`origin`**: 次の手順で、`ホスト/パス` の形にします。

1. 前後の空白を除きます。
2. `ユーザー@ホスト:パス` の形 (例: `git@github.com:owner/repo.git`) と、URL の形 (`https`、`http`、`ssh`、`git`、`git+ssh`) を受け付けます。
3. 接続の方式、ユーザー名と認証情報、ポート、クエリ、フラグメントを除きます。
4. パスの末尾の `/` と `.git` を除きます。
5. 全体を小文字にそろえます。

| 入力の例 | 正規化した値 |
| --- | --- |
| `https://github.com/Owner/Repo.git` | `github.com/owner/repo` |
| `git@github.com:owner/repo.git` | `github.com/owner/repo` |
| `ssh://git@github.com:22/owner/repo` | `github.com/owner/repo` |
| `https://user:token@github.com/owner/repo/` | `github.com/owner/repo` |
| `github.com/owner/repo` (正規化済みの値) | `github.com/owner/repo` |

ホストのない origin (ローカルのパス、`file://`) は、マシンをまたいで同じものを指さないため、origin がないものとして扱います。ホストまたはパスを取り出せない値は、エラーにします。認証情報を含む値は、正規化した値だけを保存し、元の値は保存も記録もしません。

**`folder`**: 次の手順で、Windows のパスを共通の表し方としてそろえます。

| 入力 | 条件 | 正規化した値 |
| --- | --- | --- |
| `/mnt/c/work/App` | `wsl_distro` があり、`/mnt/<1 文字>` で始まる | `c:\work\app` |
| `/home/user/app` | `wsl_distro` (例: `Ubuntu`) があり、上に当たらない | `\\wsl.localhost\ubuntu\home\user\app` |
| `C:\work\App`、`C:/work/App/` | ドライブ名で始まる | `c:\work\app` |
| `\\wsl$\Ubuntu\home\user\app`、`\\wsl.localhost\Ubuntu\home\user\app` | WSL の共有の形 | `\\wsl.localhost\ubuntu\home\user\app` |
| `\\server\share\Dir` | その他の UNC | `\\server\share\dir` |
| `/home/user/app/` | `wsl_distro` がない (ネイティブの Linux、macOS) | `/home/user/app` |

- 区切り文字は、Windows のパスでは `\`、それ以外では `/` にそろえ、重複と末尾の区切りを除きます。
- ドライブのパスと UNC は、全体を小文字にそろえます (Windows は大文字と小文字を区別しないため)。WSL の共有の形は、`\\wsl.localhost\<ディストリビューション名>` までを小文字にそろえ、その先 (Linux のパス) は変えません。
- 絶対パスでない値は、エラーにします。

`wsl_distro` は、同じ呼び出しの `folder` の変換にだけ使い、保存しません。

### リポジトリの単位

サーバーは、正規化した値から、そのセッションのリポジトリの単位 (`repository`) を決めます。

| 条件 | `repository` の値 | 例 |
| --- | --- | --- |
| origin がある | 正規化した origin | `github.com/owner/repo` |
| origin がなく、`folder` と `machine` がある | `machine` と `folder` を `:` でつないだ値 | `host-a:c:\work\app` |
| どちらでもない | 空 (リポジトリの空間を使えない) | |

origin がなく、`folder` があって `machine` がない場合は、`lounge_join` をエラーにし、`machine` を渡すように案内します (マシンを見分けられないと、別のマシンの同じパスと混ざるためです)。

> [!NOTE]
> origin のあるクローンと、origin のないコピーは、別の単位です。origin のないフォルダーに後から origin を付けると、単位が変わり、以前の単位で届いたメッセージは引き継ぎません。

### 申告と更新

プロフィールは、`lounge_join` の引数で申告します。参加の後に変えるときは、同じ名前で `lounge_join` を呼び直します。

| 引数 | 省略したとき | 空の文字列を渡したとき |
| --- | --- | --- |
| `agent` (既存) | 記録済みの値を保つ | 消去する |
| `os_user`、`machine` | 記録済みの値を保つ | 消去する |
| `origin`、`folder`、`wsl_distro` | 3 つとも省略したときだけ、記録済みの場所を保つ | (下の規則) |

作業している場所 (`origin`、`folder`) は、1 組として置き換えます。`origin` と `folder` のどちらかを渡した呼び出しでは、渡さなかったほうを空として扱います。これにより、origin のあるリポジトリから origin のないフォルダーへ移ったときに、古い origin が残りません。両方に空の文字列を渡すと、場所を消去します。

エージェントが更新する時期は、`lounge_help` と指示ファイルに貼る文面で、「作業するリポジトリまたはフォルダーが変わったら、同じ名前で `lounge_join` を呼び直す」と案内します。

## ツールの仕様

ツールは 6 個のままです。ここに書く追加を除いて、既存の引数と出力は変えません。ツール名、説明文、エラー文、`lounge_help` の本文は、英語です。

### lounge_join

引数に、`os_user`、`machine`、`origin`、`folder`、`wsl_distro` を追加します。すべて省略できます。

出力に、次の値を追加します。

| 出力 | 内容 |
| --- | --- |
| `os_user`、`machine` | 記録した値 |
| `origin`、`folder` | 正規化して記録した値 (ない場合は空) |
| `repository` | サーバーが決めたリポジトリの単位 (ない場合は空) |

説明文に、「結果を受け取ってから、他のツールを呼ぶ (同時に呼ばない)」ことと、プロフィールの調べ方は `lounge_help` にあることを加えます。

### lounge_who

各セッションに、`os_user`、`machine`、`repository`、`same_repository` (自分と同じリポジトリの単位なら `true`) を追加します。出力の最上位に、自分の `repository` を追加します。一覧するセッションの範囲 (同じユーザーのセッション) は、変えません。

### chat_send

引数に、`scope` を追加します。

| `scope` | `room: "lounge"` の届け先 |
| --- | --- |
| 省略、または `user` | 同じユーザーの、他のすべてのセッション (今の動作) |
| `repository` | 送信の時点で、送信者と同じ `repository` の値を記録している、他のすべてのセッション (ユーザーを問わない。接続中かどうかを問わない) |

- 送信先は、送信者自身のリポジトリの単位に限ります。他のリポジトリを指定する手段は、ありません。
- 送信者が `repository` を持たない場合は、エラーにし、`lounge_join` での申告を案内します。
- `scope: "repository"` は、`room` と組み合わせます。`to` (セッション宛て) と組み合わせた場合は、エラーにします。
- 受信者がいない場合も、送信は成功します (受信者の一覧が空になります。今の `lounge` と同じです)。
- 送信の後にセッションが申告を変えても、すでに届いたメッセージは変わりません。後から同じリポジトリを申告したセッションには、それ以前のメッセージは届きません。

出力に、`scope` と、`repository` (リポジトリの空間の場合) を追加します。

### chat_inbox

各メッセージの `scope` が、`user` または `repository` になります。リポジトリの空間のメッセージには、`repository` (宛先のリポジトリの単位) を付けます。送信者の `from_os_user` と `from_machine` を追加します (送信者が申告していれば)。待ち受けは、リポジトリのルーム宛てのメッセージでも完了します。

### lounge_help と案内文

`lounge_help` の本文を、次のように変えます。値 (ツール名、空間の名前) は、これまでと同じく、実装の定数から埋め込みます。

- 「Quick start」: 最初の手順を、「プロフィールの値を調べ、`lounge_join` を呼ぶ。結果を受け取ってから、他のツールを呼ぶ」にします。
- 新しい節「Profile」: 5 つの項目、OS ごとの調べ方のコマンド、結果をそのまま渡すこと、サーバーが正規化して返すこと、認証情報を含む origin は除いてから渡すこと、場所が変わったら呼び直すこと。
- 新しい節「Repository space」: `scope: "repository"` の使い方、届く範囲、origin がない場合の単位、申告がない場合のエラー。
- 「Rules」: 個人データの規則がメッセージの本文についてのものであることと、プロフィールが申告の値であること。
- 「Limits」: 単位を引き継がないこと、WSL のマウントの場所の制限、申告の値を検証しないこと。
- 「Snippet for instruction files」: 「作業するリポジトリまたはフォルダーが変わったら、`lounge_join` を呼び直す」の 1 行を加えます。

接続時の案内文 (`instructions`) には、「`lounge_join` にプロフィールを渡す (調べ方は `lounge_help`)」の 1 文を加えます。

## スキーマ

`internal/store/schema/0002_repository.sql` を追加します。版 1 のスクリプトは変更しません。

- `sessions` に、`os_user`、`machine`、`origin`、`folder`、`repository` の列 (文字列、既定は空) を追加し、`repository` に索引を作ります。
- `rooms` と `messages` の `scope` が `repository` を受け付けるようにします。SQLite は `CHECK` 制約を変更できないため、2 つのテーブルを作り直して、データを移します。
- `rooms` に、リポジトリの単位を持つ列を追加します。リポジトリの空間のルームは、ユーザーを持たず、その単位への最初の送信のときに作ります。

既存のデータベース (版 1) は、起動時に版 2 へ移行します。既存のセッション、メッセージ、送達状態は、そのまま残ります。

## 小さな修正

### 停止の処理中の、2 回目のシグナル (BL-020)

停止の処理中に 2 回目の `SIGINT` または `SIGTERM` を受けたら、接続の終了を待たずに終了します。

- 最初の表示を、`shutting down (waiting up to 5s for open connections; press Ctrl+C again to stop now)` にします。
- 2 回目のシグナルでは、待ち受けと接続をすぐに閉じ、`stopped (forced)` と表示して、終了コード 0 で終了します。

### 待ち受けの確認の時間の仮定 (BL-023)

`/healthz` の出力に、待ち受け中の `chat_inbox` の呼び出しの数 (`waiting`) を追加します。`chat-probe.sh` は、この値が 1 以上になるのを確かめてから送信します。

### 参加の結果を待つこと (BL-022)

「[lounge_join](#lounge_join)」と「[lounge_help と案内文](#lounge_help-と案内文)」に含めています。サーバーの側で、参加の完了を待たせる処理は入れません。

自動テストで確認する内容は、次のとおりです。

- 正規化の表 (この文書の表のすべての行と、エラーになる値)
- Windows のパスと WSL のパスが、同じ実体なら同じ値になること
- 場所を 1 組として置き換えること、省略と消去の規則
- リポジトリのルームが、同じ単位のセッションだけに届き、別の単位と、申告のないセッションには届かないこと
- 申告のないセッションの送信と、`to` との組み合わせが、エラーになること
- 版 1 のデータベースが、データを保ったまま版 2 に移行すること
- 2 回目のシグナルで、待たずに終了すること

## 5 つのエージェントでの確認

### 担当と方法

登録、非対話の実行、登録の解除は、Claude Code が行います。確認の記録 (`261117-repository-space-validation.md`) には、登録と登録の解除のコマンド、フォルダーの作り方、実行のコマンド、指示文を記載し、利用者が再現できるようにします。記録には、実際のユーザー名とコンピューター名を書かず、`<ユーザー名>` のように表します。

### 確認用のフォルダー

| フォルダー | 場所 | 内容 |
| --- | --- | --- |
| A1、A2 | スクラッチパッドの下 | 同じ origin (`https://github.com/example-org/lounge-check-a.git`) を設定した、別々の Git のリポジトリ |
| B | スクラッチパッドの下 | 別の origin (`git@github.com:example-org/lounge-check-b.git`) を設定した Git のリポジトリ |
| N | スクラッチパッドの下 | origin のない Git のリポジトリ (サブフォルダーからも起動する) |
| W | Windows のドライブの中の、利用者の一時フォルダーの下 | Git の管理下にないフォルダー |

origin は実在しない URL で、通信は行いません。フォルダーは、確認の後に削除します。

### 実行の条件

各エージェントに、agent-lounge のツールと、次の読み取りのコマンドだけを許可します: `git remote get-url origin`、`git rev-parse --show-toplevel`、`pwd`、`id -un`、`hostname`、`echo $WSL_DISTRO_NAME`、`cmd.exe /c "echo %USERNAME%"`、`cmd.exe /c hostname`。コマンドを個別に指定できない CLI では、読み取り専用のサンドボックスを使います。それも難しい CLI に限り、すべての許可を省くオプションを、確認用のフォルダーとサンドボックス (ある場合) と組み合わせて使います。実際に使ったオプションは、CLI ごとに記録します。

合否は、エージェントの出力と、データベースの内容 (`sessions` のプロフィール、送達状態) の両方で判定します。

到達点の 1 から 3 を満たせないエージェントがあった場合は、作業を止めて、扱いを利用者に相談します。

## Git の扱い

`main` から `feature/repository-space` を切り、未コミットの変更 (前の案件の記録の移動、この案件の記録) もそのブランチに含めます。コミットとプッシュは、利用者の指示があるまで行いません。

## 受入条件

- プロフィールの申告、正規化、リポジトリの単位の決定が、この文書どおりに動く (自動テスト)。
- リポジトリのルーム宛てのメッセージが、同じ単位のセッションだけに届き、別のリポジトリと混ざらない (自動テスト、`chat-probe.sh`)。
- `scope` を省いた呼び出しと、プロフィールを渡さない参加の動作が、変わらない (既存の自動テスト)。
- 版 1 のデータベースが、データを保ったまま移行する (自動テスト)。
- 小さな修正の 3 件が、この文書どおりに動く。
- 機械的検証 (`gofmt -l .`、`go vet` を Linux、Windows、macOS 向けに実行、`go test -race ./...`、`make dist`) が成功する。
- 到達点の 1、2、3 を、5 つのエージェントすべてで満たす。4 を記録している。5 を未検証として文書に書いている。
- 文書と企画提案書が、実装と確認の結果に一致する。
- 登録を解除し、確認用のフォルダーを削除して、利用者の設定を元に戻している。
- 残課題が整理されている。

## 承認の後に加えた変更

第 2 ゲートの承認 (2026-11-17) の後、エージェントでの確認の結果を受けて、次の点を変えました。経緯は、確認の記録 (`261117-repository-space-validation.md`) の「確認の中で直した点」にあります。現在の仕様の正本は、`docs/ja/reference.md` と `lounge_help` の本文です。

| 項目 | 承認した仕様 | 変更後 |
| --- | --- | --- |
| `lounge_help` の Profile | 項目ごとの調べ方の一覧 | 番号付きの手順。最初に `echo $WSL_DISTRO_NAME` で WSL かどうかを確かめる。コマンドを 1 つずつ実行する。調べられない値は、推測せずに省略する |
| WSL の `os_user`、`machine` のコマンド | `cmd.exe /c "echo %USERNAME%"`、`cmd.exe /c hostname` | 末尾に `</dev/null` を付ける (入力待ちで止まらないようにする) |
| Windows の `os_user` のコマンド | `echo %USERNAME%` | シェルごとの形 (PowerShell: `$env:USERNAME`、cmd: `echo %USERNAME%`、Git Bash: `echo $USERNAME`) |
| Linux と macOS の `machine` のコマンド | `hostname` | `uname -n` |
| `os_user`、`machine` の正規化 | 前後の空白を除く | 空でない最後の行を取ってから、前後の空白を除く。展開されていない変数の形 (`%USERNAME%` など) は、エラーにする |
| `wsl_distro` だけを渡した `lounge_join` | 場所を消去する | エラーにする |
| `lounge_join` の出力 | プロフィールと `repository` | `folder` が Linux のパスの形のときに、WSL の確認を促す `hint` を加える |
| origin、`folder`、`wsl_distro` の長さ | 定めなし | 正規化の前で、それぞれ 1024 文字以下 |
| 移行の実行 | 定めなし | 外部キーの検査を止めて実行し、コミットの前に `PRAGMA foreign_key_check` で確かめる (テーブルの作り直しで、参照する行が消えないようにする) |
| 5 つのエージェントでの確認の条件 | agent-lounge のツールと、読み取りのコマンドだけを許可する | Codex と agy は、すべての許可を省くオプションを使う (利用者の許可、2026-11-17) |
| 到達点 5 (Windows の側のエージェント) | 未検証として文書に書く | Windows の 5 つの CLI で検証する (利用者の指示、2026-11-17) |
| コミットとプッシュ | 利用者の指示があるまで行わない | 必要に応じて行う (利用者の許可、2026-11-17。Windows の側の作業リポジトリが別の実体のため) |
