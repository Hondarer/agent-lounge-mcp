### 調査で確認した事実

ユーザーが明示した内容は、次の 2 点です。

- 実装は段階的に行い、初めは localhost 折り返しのチャットサーバーとします (対話での指示)。
- 今回の計画は、各エージェント同士が簡単な会話を疎通確認できるまでとします (対話での指示)。

スケルトンの現状は、次のとおりです。

- サーバーは `serve` で起動し、`/mcp` で Streamable HTTP に応答します。ループバック以外の待ち受けは拒否します。
- ツールは `lounge_info` だけです。企画提案書の 12 個のツールは、まだありません。
- 接続元の認証はありません。`users` テーブルはありますが、行を作る手段がありません。
- `users`、`sessions`、`rooms`、`messages`、`deliveries` の 5 テーブルがあり、`shared` の空間の `lounge` ルームは作成済みです。テーブルを操作する処理は、まだありません。
- ルームに参加しているセッションを記録するテーブルはありません。

このマシン (Linux (WSL)) に入っているエージェントの CLI は、次のとおりです。MCP の登録方法は、各 CLI のヘルプ表示で確認した範囲です。実際の接続は、どれも確認していません。
