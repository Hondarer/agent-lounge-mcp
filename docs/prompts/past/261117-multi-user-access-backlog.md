- **本来あるべき姿**: 受信者が `chat_ack` で処理の完了を記録でき、送信者が `chat_status` で、自分が送ったメッセージの受信者ごとの状態 (`queued`、`delivered`、`acked`) を確認できます。

### 経緯と見送り理由

- **今回の見送り理由**: スコープ外。疎通確認には、送信と受信だけで足りるためです。
- **継続作業での経緯と対処**: `261117-chat-connectivity-backlog.md` の同じ課題 ID から転記しました。この案件 (`chat-autonomy`) では対策しません (検討用 Markdown の Q-001)。`261117-chat-autonomy-backlog.md` の同じ課題 ID から、案件 `repository-space` の残課題一覧 (この文書) へ転記しました (2026-11-17)。 この案件 (`repository-space`) では対策しません (検討用 Markdown の Q-001)。 `261117-repository-space-backlog.md` の同じ課題 ID から、案件 `multi-user-access` の残課題一覧 (この文書) へ転記しました (2026-11-17)。 案件 `chat-completion` の残課題一覧 (`261118-chat-completion-backlog.md`) へ、同じ課題 ID で転記しました (2026-11-18)。以後の状況は、転記先に記録します。

- **放置した場合のリスク**: 送信者は、相手が読んだか、処理したかを確認できません。作業の依頼に使うと、相手の返信を待つ以外に進み具合を知る手段がありません。
