## 2. トークンの有効期限

### 2.1. データ

スキーマの新しい版 (`internal/store/schema/0006_token_expiry.sql`) で、`users` に 2 つの列を足します。

| 列 | 型 | 内容 |
| --- | --- | --- |
| `token_expires_at` | 整数 (ミリ秒。NULL 可) | トークンの期限の時刻。NULL は期限なし |
| `last_used_at` | 整数 (ミリ秒。NULL 可) | トークンで認証した要求の、最後の時刻 (第 3 章)。NULL は記録なし |

既存のユーザーは、どちらも NULL (期限なし、記録なし) になります。期限は、サーバーの時計で判定します。現在の時刻が期限の時刻以降であれば、期限切れです。

### 2.2. 管理コマンド

```text
agent-lounge-mcp user add <名前> [--expires-in <期間>] [--db FILE]
agent-lounge-mcp user rotate <名前> [--expires-in <期間>] [--db FILE]
agent-lounge-mcp user expiry <名前> (--in <期間> | --never) [--db FILE]
agent-lounge-mcp user list [--db FILE]
```

- 期間は、サーバーの期間のオプションと同じ形です (`90d`、`1d12h`、`36h`)。0 以下の値は、使い方の誤り (終了コード 2) にします。期限は、コマンドを実行した時刻に期間を足した時刻です。
- `user add` と `user rotate` で `--expires-in` を指定しない場合、発行するトークンは期限なしです。`user rotate` は、前のトークンの期限を引き継ぎません。
- `user expiry` は、トークンを変えずに、期限だけを変えます。`--in` と `--never` は、どちらか 1 つが必須です。期限が切れた後のトークンも、延ばせば、また使えます。存在しないユーザーと `local` は、他のコマンドと同じエラー (終了コード 1) です。
- `user add` と `user rotate` は、標準エラーの案内に、期限の日時 (RFC 3339 の UTC)、または期限がないことを 1 行足します。標準出力は、今と同じく、トークンだけです。
- `user expiry` は、標準出力に、変更の結果 (ユーザー名と、新しい期限の日時または期限がないこと) を 1 行で出します。
- `user list` は、末尾に列 `EXPIRES` を足します。値は、期限の日時 (RFC 3339 の UTC)、期限なしと `local` は `-` です。既存の列の位置と内容は、変えません (`LAST_USED` の値の決め方は、第 3 章)。

### 2.3. 認証

| 要求 | 応答 |
| --- | --- |
| 期限が切れたトークン | 状態コード 401、`WWW-Authenticate: Bearer error="invalid_token"`。本文は、期限が切れたことと対処 (サーバーの管理者に、期限の延長 (`user expiry`) か、発行し直し (`user rotate`) を頼む) を、英語の 1 文で伝えます。トークンは含みません。トークンが必須でない構成でも、`local` にはしません |
| それ以外 | 今と同じ |

- 期限切れは、要求ごとの照合で判定するため、次の要求から効きます。`user expiry` での延長も、次の要求から効きます。
- 待ち受け中の `chat_inbox` は、今の「トークンがまだ有効か」の確認 (5[秒] ごとと、新着が届いたとき) に、期限切れを含めます。期限が切れた場合は、待ち受けをやめ、メッセージを渡さずに、期限が切れたことと対処を示すエラーを返します。発行し直しとユーザーの削除の場合のエラー文は、今と同じです。
- 期限が切れても、ユーザー、セッション、メッセージ、メモリは残します。定期的な削除の対象と期間は、変えません。
- トークンのない要求 (ユーザー `local`) には、期限がありません。

> [!NOTE]
> 期限切れを本文で伝えると、そのトークンが以前は有効だったことが、トークンを持つ相手に分かります。利用者が、設定の誤りと期限切れを見分けて対処できることを優先しました。

## 3. 最後の利用日時

- サーバーは、有効なトークンで認証した要求のたびに、そのユーザーの `last_used_at` を、現在の時刻にします。書き込みは、同じユーザーについて、1 分に 1 回までにします (サーバーのプロセスの中で、ユーザーごとに前の書き込みの時刻を覚えます)。
- 書き込みに失敗した場合は、ログに書き、要求は続けます。
- 期限切れや無効なトークンの要求、トークンのない要求 (ユーザー `local`) では、記録しません。
- `user list` の `LAST_USED` は、`last_used_at` と、そのユーザーのセッションの最終利用時刻のうち、新しいほうです。どちらもなければ `-` です。`local` は、今と同じく、セッションの最終利用時刻だけで決まります。
- SQL は、`internal/store/` に置きます。

## 4. マシンの名前

### 4.1. 使い方の案内

`lounge_help` の Profile の、WSL の行を変えます (`internal/tools/help.go`)。

- 今: `cmd.exe` を実行できない場合は、`os_user` と `machine` を省く。
- 変更後: `cmd.exe` が失敗する、または見つからない場合 (サンドボックスの中) は、`machine` に `cat /etc/hostname` の出力を使い、`os_user` は省く。

`lounge_join` の `machine` の引数の説明と、origin のないフォルダーで `machine` がない場合のエラー文 (`internal/tools/lounge.go`) にも、同じ手段を書きます。`lounge_help` の本文は、既定の設定で 18,000 バイト以下を保ちます (既存のテスト)。

> [!NOTE]
> WSL の既定では、Linux の側のホスト名 (`/etc/hostname`) は、Windows のコンピューター名と同じです。確かめた 3 つの環境 (サンドボックスなし、Codex のサンドボックス、agy の隔離された環境) で、同じ値でした。`/etc/wsl.conf` の `[network]` の `hostname` で変えた環境では、Windows の側のセッションと値が合わず、origin のないフォルダーを Windows の側と共有できません。これは、文書の制限事項に書きます。

### 4.2. 受け付けない値

`lounge_join` は、`machine` の正規化の後の値 (小文字) が `sandbox`、`localhost`、`localhost.localdomain` のどれかである場合、エラーにします (`internal/profile/` の `Machine`)。エラー文は、その値がマシンを区別しないことと、`cat /etc/hostname` の出力を使うか `machine` を省くことを、英語で伝えます。参加は行われず、記録済みの値は変わりません。

## 10. 受入条件

1. `go vet ./...` と `go test ./...` が通る (WSL。Windows の側でも `go test ./...`)。
2. 期限の機能に、自動テストがある: 版 5 のデータベースの移行、`--expires-in` の発行、`user expiry` の 2 つの形と誤った指定、`user list` の列、期限切れの 401 と本文、延長の後に再び使えること、待ち受け中の `chat_inbox` の打ち切り、期限なしのトークンの動作が変わらないこと。

5. 検証の基盤の自己試験が、WSL と Windows で通る。Windows で `ResourceWarning` が出ない。
6. 第 6 章の a から k を実施し、結果 (検証済、未検証、制限あり、`-`) を、文書の「検証済みの範囲」と確認の記録に書いている。
7. 第 7 章と第 8 章のとおり、文書を更新している。
8. サブエージェント (Opus) のレビューを受け、指摘を直している、または直さない理由を記録している。
9. 残課題一覧を再構築し、残ったものだけにしている。
